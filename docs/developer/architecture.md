# 設計と責務の分担

[READMEへ戻る](../../README.md) · [開発・配布ガイド](guide.md)

ChatPaletteの入口は `main.ahk`。Ctrl＋Alt＋Qで入力用パレットを開き、管理画面は別ウィンドウで構築する。AHKが文字列入力とUIを担当し、PowerShellがブラウザーのUI Automationと動画情報の取得を担当する。弾幕のEnter送信は実装しない。

## UIと状態の分離

| 状態 | 所有・用途 |
|---|---|
| `TargetBrowserHwnd` / `DetectedChannel` | パレットの入力先と検出結果 |
| `InputProfileIndex` | 実際の弾幕入力に使う配信者 |
| `EditProfileIndex` / `EditScopeShared` | 管理画面で編集中の対象。入力選択を変更しない |
| 配信者の `Id` | 配列の削除・並べ替え・取り消しをまたいで同一配信者を追跡する永続ID |
| 弾幕の `Slot` | 0＝未割当、1／2＝スコープ内のショートカット枠。表示順とは独立 |
| パレットのリアクション選択 | 今回のリアクション用。明示的な保存まで標準設定を変更しない |
| `DefaultReactionKind` / `DefaultReactionCount` / `DefaultReactionIntervalMs` / `ReactionShortcut` | 全チャンネル共通の保存済み標準設定。キー実行はこちらを使用 |
| `ActiveReactionJob` | 開始時点の種類・回数・間隔・動画・ウィンドウを固定した実行状態 |
| `LibraryHistory` | 弾幕・配信者の変更前データ。起動中の直近30件。リアクション設定を含めない |

自動判別が失敗・チャンネル未連携の場合、以前の配信者の弾幕をパレットへ表示しない。実行時にも入力先を再検証する。削除等の確定時は入力用・編集用の選択をIDから引き直し、見つからなければ0にする。次の配列要素へ暗黙に切り替えない。

## ファイル配置

起動入口の `main.ahk` と `VERSION` はトップに置き、実装は `src/` にまとめる。フォルダー構成を保ったまま配布する。

| ディレクトリ | 役割 |
|---|---|
| `src/app/` | 起動・終了、設定の復旧 |
| `src/ui/` | 共通表示処理、ヘルプ、診断、進捗 |
| `src/ui/palette/` | 入力用パレット |
| `src/ui/management/` | 管理画面と編集ダイアログ |
| `src/library/` | 弾幕・配信者の管理 |
| `src/input/` | 弾幕入力の制御と実行 |
| `src/reactions/` | リアクション実行の制御 |
| `src/shortcuts/` | キーの検証・登録・呼び出し |
| `src/settings/` | 設定の定義・検証・保存 |
| `src/browser/` | ブラウザー連携、名前付きパイプ、PowerShellワーカー |
| `data/` | 利用者の設定・キャッシュ。Git・配布対象外 |
| `tests/` | 独立した環境での回帰テスト |
| `scripts/` | 開発・配布用の処理 |

AHKの実行基準はトップの `main.ahk` とする。PowerShell内のモジュール読み込みは各ファイルの `$PSScriptRoot` を基準にし、既定のデータ保存先はプロジェクト直下の `data/` とする。カレントディレクトリに依存させない。

## モジュール

- `main.ahk`：初期化、モジュールの接続、常駐キーとトレイの登録。
- `src/ui/palette/palette_controller.ahk`：パレット呼び出し、自動判別の適用、画面更新の調整。
- `src/browser/browser_service.ahk`：ブラウザー要求、同時実行の抑止、画面待機の開始・終了、入力直前の検証。通信自体は `src/browser/worker_client.ahk` が担当する。
- `src/ui/palette/palette_view.ahk`：入力用パレットの構築・表示・イベント。本文を直接入力せず、入力コントローラーへ依頼する。
- `src/ui/management/management_view.ahk`：管理画面の構築、表示内容の更新、各タブの配置。
- `src/ui/management/management_dialogs.ahk`：弾幕編集・移動、キー編集、チャンネル連携のダイアログ。保存・キャンセルの寿命を管理し、確定時はサービスへ依頼する。
- `src/ui/help_view.ahk`：目的別の使い方画面。
- `src/ui/management/management_controller.ahk`：編集対象の変更、保存、標準設定の読み込み、ブラウザー照会、配信者操作の調整。編集中の配信者をIDで選び直す。
- `src/library/library_service.ahk`：弾幕・配信者の追加・編集・複製・並べ替え・移動・削除・チャンネル連携、保存、履歴。GUIと編集用の選択状態に依存しない。
- `src/library/danmaku_library.ahk`：弾幕スコープとキー枠の取得・正規化・一意な割当。
- `src/library/profile_service.ahk`：配信者ID、入力用選択の保存、チャンネル索引。管理画面の選択を扱わない。
- `src/input/input_controller.ahk`：配信者・キー枠を一度だけ解決し、本文・ウィンドウ・動画IDを確定して入力処理へ渡す。
- `src/input/text_input.ahk`：確定済みの本文を入力直前に再検証し、`SendText` で入力する。配信者を再判別しない。
- `src/shortcuts/shortcut_controller.ahk`：キー解放待ち、編集・実行中の抑止、弾幕入力の呼び出し。
- `src/shortcuts/shortcut_policy.ahk`：キーの検証・正規化・予約キー判定。GUI・登録処理に依存しない。
- `src/shortcuts/shortcut_bindings.ahk`：実行時のキー登録・解除とブラウザー限定条件。設定保存時のロールバックからも利用する。
- `src/reactions/reaction_controller.ahk`：リアクションの登録・確認・実行、開始待ち、回数・間隔・停止、実行状態。
- `src/ui/reaction_feedback.ahk`：進捗画面の初期化と表示。文言・終了状態は `ReactionExecutionStatus` から取得する。汎用の `PaletteStatusControl` の表示を実行状態として読み戻さない。
- `src/ui/window_presenter.ahk`：独自GUIの表示順序を統一。非表示でサイズ確定 → 配置・スクロール調整 → 表示・再描画。スクロールバーの変化で表示領域が変わった場合は表示前に再調整する。表示中の画面は隠し直さず、アクティブ化の有無を引数で指定する。
- `src/ui/ui_runtime.ahk`：通信待機中の画面制御、編集ダイアログの状態、操作案内。
- `src/settings/settings_store.ahk`：INIの読み書き・形式移行。長文・引用符・文字コードを保持する。
- `src/settings/settings_service.ahk`：設定スナップショット、共通設定の検証・確定、キー登録のロールバック。
- `src/settings/settings_schema.ahk`：選択肢・標準設定、`CreateReactionOptions` による明示的なリアクション設定値の生成。
- `src/app/app_lifecycle.ahk`：データ配置と起動時の設定復旧。
- `src/ui/diagnostics.ahk`：診断スナップショット、画面、コピー。
- `src/ui/panel_viewport.ahk`：診断画面のスクロール・フォーカス追従。
- `src/browser/worker_client.ahk`：補助プロセス、名前付きパイプ、要求・応答、タイムアウト。GUIに依存しない。
- `src/browser/browser_worker.ps1`：動画ID取得と要求の振り分け。
- `src/browser/browser_uia.ps1`：共通のUI Automation処理とウィンドウ所属確認。リアクション登録を読み込まない。
- `src/browser/input_target.ps1`：フォーカスされた入力欄と祖先の検証。共通UIAモジュールだけで単独読み込みできる。
- `src/browser/reaction_automation.ps1` / `src/browser/reaction_store.ps1`：リアクションの検出・操作と登録情報の検証・保存。
- `src/browser/video_metadata.ps1`：YouTube oEmbedと動画情報キャッシュ。

`ActiveEditorDialog` は表示中の管理画面ではなく、入力を抑止する編集中ダイアログの情報を保持する。実際のダイアログ名で案内し、終了時には開始前のウィンドウ有効状態を復元する。

パレット・管理画面の配置は、作成時に保持したコントロール参照で行う。ボタンや説明の表示文言を配置対象の識別に使わない。

## 保存と移行

内部の `DefaultReactionKind`／`DefaultReactionCount`／`DefaultReactionIntervalMs` は、INIでは従来どおり `ReactionDefault`／`ReactionCount`／`ReactionInterval` として保存する。内部改名による形式移行は行わない。

INIの `General.Schema=3` は配信者IDと弾幕の明示的なキー割当を保存する。旧形式の `Slot` 未指定項目は先頭2件を1／2、それ以外を0に移行する。重複・範囲外の枠は解除する。移動・複製では割当を持ち越さず、並べ替えは項目の枠を保持する。

旧配信者の `Reaction` は読み込まず、次回保存時に出力しない。共通の種類・回数・間隔・キーは維持する。形式更新前に元のINIを `settings.ini.backup-日時-番号` へコピーし、退避に失敗した場合は更新しない。

文字列値は外側の引用符を1組だけ除去して読む。UTF-16／UTF-8 BOMと、従来のBOMなしシステム文字コードを扱う。改行を含む文字列は保存前に拒否する。INI全体をUTF-16 BOM付きで一時ファイルへ書き出してから置換し、保存成功後に実行中データを更新する。

弾幕・配信者の取り消しはライブラリだけを復元する。保存先への書き込みが成功するまで履歴を消費しない。管理画面を閉じても履歴は保持し、終了または設定の再読み込みで破棄する。選択式の共通設定は即時保存、弾幕本文とキー編集は明示的な保存・キャンセルを用いる。

## 変更時の規則

1. GUIから配信者・弾幕を直接変更しない。`ExecuteDanmakuCommand`／`ExecuteProfileCommand` に対象IDと値を渡す。サービス内の `CommitLibraryChange` が保存後に公開する。呼び出し元の候補に他の設定が含まれていても保存対象へ取り込まない。
2. サービスへGUIの選択位置を渡さず、配信者IDを渡す。編集用の選択から入力用の選択を更新しない。入力選択の変更には `SaveInputProfileSelection` を使う。
3. キー割当は同一スコープ内で一意にし、0を未割当として保持する。
4. 共通リアクション設定は `SaveReactionDefaults` で検証・確定する。キー登録失敗・保存失敗では元へ戻す。
5. 実行中ジョブの条件をGUI変更から書き換えない。処理を並列に発行しない。
6. 通信中はUI変更を抑止し、元から無効だったウィンドウを通信終了時に有効化しない。
7. 結果不明のリアクションは再送しない。表示文言から実行状態を判断しない。
8. 配信者・弾幕0件は正常。初回や最後の削除時に代替のサンプルを作らない。

## リアクションの処理間隔

各回の処理開始を高精度カウンターで記録し、処理時間を指定間隔から差し引いて待機する。0（待機なし）は追加待機なし。単一のループで要求と応答を順番に処理し、遅れた期限に追いつくための連続送信は行わない。各回と短い待機区間で停止イベントを処理する。進捗の描画だけを100ms間隔で集約し、開始・終了は即時描画する。描画の間引きは回数計上と操作間隔に影響させない。標準設定は100msで、既存の保存済み間隔は維持する。

ボタンの属性はCacheRequest/GetUpdatedCacheで毎回まとめて取得する。過去の属性値は再利用しない。所属ウィンドウはNativeWindowHandleを条件にしたTreeWalker.Normalizeで確認する。5種類の一意な照合、表示・有効状態、動画変更、最前面確認と1秒ごとの再検索を維持する。

## 通信と障害処理

補助プロセスは必要時に起動する。要求・応答は長さ付きUTF-8フレームでローカルの名前付きパイプを通す。要求の連番・対象ウィンドウを照合し、接続相手のプロセスIDも確認する。通常の要求は最大8秒、動画の再確認は最大2.5秒で待機を打ち切る。

補助プロセスは接続時と応答を書き終えた時に、同じランダム名から派生した自動リセットの名前付きイベントを通知する。AHKは[MsgWaitForMultipleObjectsEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-msgwaitformultipleobjectsex)で通知または画面入力を待ち、AHKのメッセージ処理を実行する。待機は最大50msずつに区切り、通知のないクラッシュとタイマーも確認する。通知は起床のきっかけであり、応答フレームの検証を置き換えない。終了・タイムアウト時にはパイプとイベントの両方を閉じる。

通信失敗時は接続と補助プロセスを整理する。次の要求で再起動できるが、失敗した要求を自動再実行しない。特にリアクションは、操作後に通信が切れた場合に実行済みか判断できないため、結果不明を再送しない。

リアクションの開始待ちは、その実行のジョブを保持する。キー解放待ちや通信の後に同じジョブが有効か確認し、中止後に作られた別のジョブを古い処理の後始末で消さない。

通信のためにディスクへ要求・応答ファイルを書き出すことはない。INIは設定変更時、ボタン登録JSONは登録時、動画キャッシュは新たな情報を取得したときに保存する。

## 自動判別とチャンネル連携

ブラウザーのURL欄から現在の動画IDを取得し、動画IDに対応する配信者情報をキャッシュまたはoEmbedから解決する。取得後に動画IDを再確認し、途中で動画が変わっていれば結果を適用しない。

チャンネル連携は配信者URLから正規化したチャンネルのパスをキーにする。表示名の類似度や部分一致では判定しない。保存済みの配信者を索引化し、同一キーが複数あれば曖昧なチャンネル連携として扱う。ハンドル等の変更に追従する不変IDへの変換は行っていない。

現在の動画IDだけが必要な場合は、共通要求 `browser_context` を利用する。ワーカーの共通処理で応答し、リアクションの検出・登録や配信者情報の取得は実行しない。

## 入力対象の検証

弾幕の配信者とキー割当は `ResolveDanmakuInput` で一度だけ解決する。確定した本文・動画IDを `DeliverText` に渡し、そこで入力直前に `verify_input` を要求する。動画が変わった場合は停止し、別の配信者の同じ一覧位置へ置き換えない。自動判別OFFでも省略しない。動画ID・対象ウィンドウ・フォーカス・編集可能性・表示状態を検証し、Web文書内のYouTube固有要素または対応する日本語・英語の入力欄名で分類する。識別不能なら停止する。

Chromiumの入力欄は `Edit` ではなく `Custom` と `TextPattern` で公開される場合がある。`ValuePattern` がなければ `TextPattern.IsReadOnlyAttribute` が明確に `false` の場合を編集可能とする。属性が未対応・混在なら許可しない。祖先は `RawViewWalker` で最寄りのWeb文書まで、最大45要素を確認し、入力欄を識別するコンテナーの省略を防ぐ。テキスト本文は取得しない。

`Edit` 型であっても編集可否を取得できなければ許可しない。読み取り専用の欄を型だけで許可することはない。

祖先要素からは識別子・クラス・種別だけを取得する。ウィンドウへの所属は開始時と終了時に確認し、終了時はフォーカス対象が変わっていないことも確認する。

画面の検索欄やアドレス欄は対象外。動画IDを取得できないチャンネルホーム等も対象外。入力欄の内容は検証要求へ含めない。UI Automation確認後にAutoHotkeyが文字を入力するため、確認と入力は完全な単一操作ではない。直前の最前面確認を行うが、極短時間のフォーカス変化まで完全に排除できるものではない。

## 動画情報キャッシュ

最大128件、取得から12時間を保持期限とする。取得失敗は5秒間メモリ上で抑制する。キャッシュ保存に失敗してもメモリ上の情報は使用できる。通信要求そのものはファイルへ書き出さない。

キャッシュの置き換えに失敗した場合も一時ファイルを削除する。削除自体が権限やロックで失敗した場合は、キャッシュの利用を妨げずに処理を継続する。

## 個人データの配置

`data/` に設定・登録JSON・キャッシュ・設定復旧用バックアップを置く。旧配置からは、移行先が存在しないファイルだけを移動する。ファイル単位の移行なので、途中で失敗しても次回起動時に残りを移行できる。同名ファイルが両方にある場合は `data/` を優先し、旧ファイルを保持する。

起動時の設定読み込み失敗は、利用者に復旧方法を選択してもらう。`--smoke` ではダイアログを表示せず非0で終了する。自動初期化は行わない。

## 画面内の通知とチャンネル連携

弾幕入力の案内は PaletteHint、標準設定の保存・読み込み結果は PaletteSettingsStatus、リアクション状態は PaletteStatusControl に表示する。進捗画面は終了時に停止ボタンを無効化して隠す。

パレットのチャンネル連携は候補チャンネルを取得し、連携先の選択と確定前の再確認を行う。新規配信者の場合は ExecuteProfileCommand の add にチャンネルを渡し、作成と連携を1回の保存・履歴にまとめる。

## 画面表示の共通契約

独自の `Gui` は `PresentWindow` または作業領域へサイズを合わせる `ShowFittedWindow` を経由して表示する。各画面は配置コールバックを渡し、診断画面はその中でスクロール範囲を調整する。固定配置の編集ダイアログはコールバックを省略できる。進捗画面は `activate=false` を指定する。

初回・非表示からの再表示は、準備に失敗した場合も非表示を保つ。表示中は隠さずサイズ・配置を更新する。ネイティブのMsgBox・InputBox・メニューはWindowsの表示処理を使用し、このGUI契約の対象外とする。

テストでは初回配置、再表示、表示中の可視性、フォーカス維持、スクロール確定、配置失敗時の非表示を確認する。共通処理を通らない独自GUIの直接表示も検出する。

リアクション設定状態の読み取りには `reaction_status` を使う。対象プロセスに保存済みの登録情報があるかだけを返し、動画情報の取得・メニュー探索・ボタン操作は行わない。`configured` は認識の成功を意味しない。

## 0.3.10の状態保持と検証

`verify_input` は入力要素を保持し、最後の動画ID取得後に同じ要素が引き続きフォーカス・表示・有効・編集可能か再確認する。AHKへの応答後の極短時間の競合は残る。

表示用の `reaction_status` は `LastBrowserOperation` を更新しない。リアクションの最終結果は `LastReactionResult` に文章・詳細・回数・操作種別・理由をまとめて確定する。進捗更新は確定済みの結果を変更しない。自アプリ内の画面判定はプロセスIDで共通化し、補助画面からパレットへの復帰でブラウザー選択を解除しない。

設定は32MiB、配信者10000件、弾幕合計100000件を上限とする。読み込み前に件数を検証し、配信者名の項目と各弾幕の空でない本文が存在することを確認する。書き込み側も同じ件数・サイズ上限を適用する。


## 小さい表示領域への対応

`PanelViewport` は固定配置の診断画面と、配置コールバックを持つ主画面で共有する。主画面では実際の領域と必要最小領域の大きい方で `LayoutPalette`／`LayoutManagement` を実行し、足りない方向にスクロールを設ける。通常サイズへ戻したときはスクロール範囲と位置を0へ戻す。

再配置の前に子ウィンドウをスクロール前の座標へ戻し、配置後に基準座標を取り直す。相対的なMove呼び出しに前回のスクロール量を累積させない。タブ内コントロールのフォーカスも監視し、操作先を表示領域へ移す。`ResizePalette`／`ResizeManagement` は実際の表示領域を使う入口、`LayoutPalette`／`LayoutManagement` は論理領域上の配置を計算する処理とする。

`ShowFittedWindow` はサイズの調整だけでなく、表示前に外枠がモニターの作業領域内に収まるよう位置も補正する。異なるDPIの実モニター間の表示品質については、実機での追加確認が必要。
