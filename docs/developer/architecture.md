# 設計と状態の所有

[文書一覧](../index.md) · [検証](testing.md)

Zigの本体プロセスは画面、設定、ライブラリ、ジョブとプロセス資源を所有します。`ChatPalette.exe` は必要な時点で、同じEXEを `-PipeName` 付きの子プロセスとして起動します。子はUI Automationと動画情報の取得を担当し、登録スナップショットを本体から受け取ります。0.8.0の実装を調べる場合は固定タグを参照してください。[0.8.0の設計](https://github.com/kitsune-udon/ChatPalette/blob/v0.8.0/docs/developer/architecture.md)

## 状態を混ぜない

| 状態 | 用途・所有者 |
|---|---|
| `Preferences.input_profile_id` | 入力に使う配信者。設定として保存する |
| `Management.editing` | 管理画面が覚える編集対象 |
| `App.target` | 操作先のブラウザーウィンドウ |
| `App.queue` | キー操作と、操作先・動画・フォーカス確認の所有者 |
| `App.preparation` と `App.reaction` | ボタン登録・送信なしの確認・リアクション送信の所有者 |
| `Client.active` | ワーカー通信が進行している間の排他 |
| `App.last_mode`・`last_state`・`last_elapsed` | 直近の診断結果 |

[本体](../../native/desktop/main.zig) は画面の有効状態に加え、操作の実行時にも所有関係とウィンドウを確認します。操作の途中から停止できるよう、ワーカーの返答を待つ間もWindowsのメッセージを処理します。停止はキューの世代を進め、返答が遅れて届いてもその後に新たな操作を発行できないようにします。

## 永続化の契約

設定は [Store](../../native/storage/store.zig) が保存します。DBの`application_id`は1129335892、対応する`user_version`は5だけです。旧版・将来版を保存設定の適用前に拒否します。WAL形式のDBでは、読み取り専用接続でもSQLiteが空のWALと共有メモリを作る場合があります。付随ファイルを含む復旧手順は[保守とトラブル対処](../user/maintenance.md)を参照してください。

- 値・件数・識別子・スロット・参照先を検証し、一つのトランザクションで保存する。
- DB確定後にライブ状態、比較基準、履歴を公開する。保存失敗では公開しない。
- `data_version`を書込ロック内で照合し、別接続による変更を上書きしない。
- キー割当は検証してDBへ保存した後、一つのキーボードフックで使うテーブルを入れ替える。保存に失敗した場合は従来のテーブルを引き続き使う。
- 順序は間隔を持つ整数で保存する。一時的な負値を使い、一意制約を保って並べ替える。
- 通常の保存はDELETEジャーナル、`synchronous=EXTRA`、外部キー検査を使う。

編集下書きとUndoのスナップショットは、共有した値を変更しません。複製は新しいIDを作り、移動・並べ替えはIDを維持します。保存済み行は比較値として保持し、画面の選択値を直接代入しません。IDの大小文字を正規化しません。

保存上限は[利用者リファレンス](../user/reference.md#上限)、設定値と行の検証は [model.zig](../../native/storage/model.zig) を参照してください。

## 弾幕入力の流れ

[本体の入力処理](../../native/desktop/main.zig) が、キー割当、入力する本文、操作の所有権を決めます。[ワーカーのキー送出処理](../../native/worker/keyboard.zig) が、再照合したウィンドウ・タブ・入力欄へWin32でキーを送ります。検索・アドレス欄や識別できない対象には入力しません。IMEは弾幕入力前にオフにし、そのまま保持します。制御文字を含む本文は、保存値を変更せず入力を拒否します。

[ショートカットの共通定義](../../native/domain/shortcuts.zig) を、設定画面、DB5、JSON2、起動時のキー割当に使います。重複判定では大文字・小文字と修飾記号の順序を区別せず、保存した文字列はそのまま往復させます。任意の操作を未割当にする場合は、操作名と空文字を保存します。設定保存とJSON取込は、DBの確定後に実行中のキー割当を更新します。

[ショートカットキュー](../../native/desktop/operations.zig) は通常キーを離した順に操作を保持します。フックが捕捉したキーの解放はフックで消費し、押下時のウィンドウが解放時も前面にあるときに操作を受け付けます。同じキーの長押しは一回として処理し、停止は押下時に後続を破棄します。別のウィンドウで新しい操作を受け付けると、前のウィンドウの待機分と確認情報を破棄します。進行中の通信が終わってから、新しい操作を実行します。同じ対象で続く操作の途中に失敗した場合は、その世代の待機分を破棄します。

対象はウィンドウ・動画・セッションで固定します。キー受付時にライブラリの版を記録し、割当を読み込んで入力するまでに変更が入れば中止します。パレットの配信者別の弾幕は、入力前に現在の配信者と動画を確認します。フォーカス確認は一度だけ消費します。フォーカス移動は最大350ms待ち、クリアは同じ入力欄か確認してから削除キーを送ります。

入力欄の確認後、ワーカーはその欄の証明を次の要求まで保持します。本体が操作の所有権を確認して `chat_enter`、`chat_clear` または `input_insert` を発行すると、ワーカーは証明を消費し、同じウィンドウ・動画・タブ・入力欄・入力種別を照合します。クリアにはフォーカス移動の証明も必要です。弾幕本文は一時共有メモリで渡し、ワーカーは読み取り専用で開きます。本体は停止や操作先の交替を受け付けると、ワーカーが送出直前に確認するイベントで許可を取り消します。結果はWindowsへのキー投入までを示し、応答喪失は結果不明として扱います。フォーカスの最終照合からキー投入までは別の処理なので、その間のフォーカス変更には競合の余地があります。[MicrosoftのSendInput仕様](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

## 登録の検出・確定・同期

[本体](../../native/desktop/main.zig) がジョブを管理し、[ワーカー](../../native/worker/reactions.zig) が登録候補の検出・確認・操作を担当します。ワーカーから返答を受け取った後も、本体はジョブが有効かを確認します。

ボタン登録はブラウザー種別ごとに5種類を識別します。保存前の中止は以前の登録を維持し、保存後の中止は確定済み登録を取り消しません。ワーカー同期に失敗してもDBは保持し、次の操作で再同期します。失敗した送信を自動再実行しません。

送信直前にも動画、ウィンドウ、前面とボタンを確認します。InvokeなどのUIA操作手段を使い、`LegacyIAccessiblePattern`も現行ブラウザーで利用する手段として残しています。「操作済み」はボタン操作の完了数で、サーバーの受理数ではありません。

## ワーカー通信と資源解放

[worker_client.zig](../../native/desktop/worker_client.zig) はローカル名前付きパイプで通信します。4バイト長とUTF-8の`key=value`を使い、最大32768バイトです。接続元のプロセス、応答の連番とウィンドウを照合します。入力確認とキー送出は要求ごとに2.5秒、その他の要求は8秒でタイムアウトします。旧版と共通の `verify_input` と `verify_chat` は確認の結果を返します。

ワーカーのSignal・Process・Pipeハンドルは一つの所有者が管理します。終了には作成時のProcessハンドルを使い、再利用されたPIDを終了しません。パイプを閉じて250ms待ち、必要なら終了を要求して2秒待ちます。終了を確認できなければハンドルを保持して失敗を通知し、再試行できる状態を残します。通信失敗と終了失敗が重なった場合は両方を保持します。

## キャッシュと画面更新

アドレス欄のキャッシュはUIA要素の所属を再確認し、現在の値を読みます。URLをキャッシュしません。最大16ウィンドウ分を保持します。リアクション要素も動画・ウィンドウ・providerの変化で無効化し、操作時に再確認します。

画面は部品を準備してから表示します。作業領域へ収まるよう配置し、構築・表示失敗では未公開画面を破棄して所有権を戻します。親の有効状態は実際の状態を記録して復旧し、他の所有者が無効化した画面を有効にしません。

一覧とドロップダウンの選択はIDで復元します。管理一覧はスナップショットをネイティブの仮想一覧に表示します。パレットは入力から100ms後に検索をまとめ、全対象を検索した上で先頭500件を表示します。

## 初期化・バックアップ

新規DBは一時ファイルへ作成し、検証・終了後に正式名へ移します。既存の不正・未対応DBを黙って初期化しません。復旧時は利用者の確認後にDBと付随ファイルを退避します。部分失敗では移動を戻し、戻せない場所とエラーも通知します。[利用者の復旧手順](../user/maintenance.md)を参照してください。

### JSON交換形式2

[JSON入出力](../../native/storage/exchange.zig) はDBと独立した交換形式2を扱います。

| オブジェクト | 必須項目 |
|---|---|
| ルート | `format: "ChatPalette"`、`version: 2`、`profiles`、`sharedItems`、`preferences`、`reactionRegistrations` |
| 配信者 | `id`、`name`、`channel`（未連携は空文字）、順序付きの`items` |
| 弾幕 | `id`、`name`、`text`、整数の`slot`（0・1・2） |
| 共通設定 | `inputProfileId`、整数の`autoMode`（0・1）、`reactionKind`、`reactionCount`、`reactionIntervalMs`、`shortcutKeys` |
| キー | `chat_send`を含む全11操作の文字列。任意操作の未割当は空文字 |
| ボタン登録 | 小文字の`browser`、5種類の`tokens`。各tokenの`name`・`id`・`class`・`type`を検証 |

登録情報の追加項目は保持します。それ以外の未知項目、必須項目の欠落、型違いを拒否します。全階層で大文字小文字を無視した重複キーを拒否し、数値文字列や小数を整数へ変換しません。厳密なUTF-8、正しいサロゲートペア、通常のエスケープ、UTF-8 BOMを受け入れ、不正UTF-8・NUL・単独サロゲートを拒否します。上限は128MiBです。

取り込み前に件数・値・外部キー・ID・スロットを検証し、現在値のJSONバックアップを作ります。検証済みのデータで稼働DBを全件置換し、確定後にキー割当と画面を更新します。成功後はUndoの履歴を消去します。

出力はBOMなしUTF-8の一時JSONへ書き、同じ読込経路で全対象値を照合してから正式名へ移します。既存ファイルを上書きしません。復元時にJSONを`settings.db`へ直接配置しません。
