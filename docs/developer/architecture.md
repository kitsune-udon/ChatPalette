# 設計と状態の所有

[文書一覧](../index.md) · [検証](testing.md)

AutoHotkeyは画面、設定、ライブラリ、ジョブとプロセス資源を所有します。PowerShellワーカーはUI Automationと動画情報の取得を担当し、設定DBには接続しません。実装とテストを契約の一次情報とします。

## 状態を混ぜない

| 状態 | 用途・所有者 |
|---|---|
| `InputProfileId` | 入力に使う配信者。設定サービスが保存する |
| `EditingProfileId` | 管理画面の編集対象。入力対象とは独立 |
| `TargetBrowserHwnd` | 確認した操作先ウィンドウ |
| `ActivePageAction` | フォーカス・クリア・入力確認の所有者 |
| `ActiveReactionJob` | 登録・確認・送信の所有者 |
| `IsBrowserOperationBusy` | アプリ側のブラウザー操作排他 |
| `RequestActive` | ワーカー通信中の要求。アプリ操作の排他とは別 |
| `LastBrowserOperation` | 診断用の直近結果。操作権限には使わない |

[操作ポリシー](../../src/app/operation_policy.ahk)を画面の有効状態と実行時検査で共有します。停止は常に受け付け、編集中・通信中・ジョブ実行中に許可する操作を明示します。設定編集は専用の所有者から確定します。画面が無効という理由だけで実行時検査を省略しません。

[RuntimePorts](../../src/app/runtime_ports.ahk)はOS・入力・ワーカーの読取境界をテストで差し替えます。`BrowserProcessName`をブラウザー判定と登録表示で共有し、ネイティブ判定の`NativeIsBrowser`は差し替えを参照しません。

## 永続化の契約

設定は[SettingsRepository](../../src/settings/settings_repository.ahk)が保存します。DBの`application_id`は1129335892、対応する`user_version`は5だけです。旧版・将来版を保存設定の適用前に拒否します。WAL形式のDBでは、読み取り専用接続でもSQLiteが空のWALと共有メモリを作る場合があります。付随ファイルを手動削除しません。形式番号だけを書き換えても互換性は得られません。

- 値・件数・識別子・スロット・参照先を検証し、一つのトランザクションで保存する。
- DB確定後にライブ状態、比較基準、履歴を公開する。保存失敗では公開しない。
- `data_version`を書込ロック内で照合し、別接続による変更を上書きしない。
- キー登録と設定保存は共通の確定処理を使う。失敗時は実行時のキーを復旧し、復旧失敗も通知する。
- 順序は間隔を持つ整数で保存する。一時的な負値を使い、一意制約を保って並べ替える。
- 通常の保存はDELETEジャーナル、`synchronous=EXTRA`、外部キー検査を使う。

編集下書きとUndoのスナップショットは、共有した値を変更しません。複製は新しいIDを作り、移動・並べ替えはIDを維持します。保存済み行は比較値として保持し、画面の選択値を直接代入しません。IDの大小文字を正規化しません。

保存上限は[利用者リファレンス](../user/reference.md#上限)、値の定義は[settings_schema.ahk](../../src/settings/settings_schema.ahk)、行検証は[library_storage_plan.ahk](../../src/settings/library_storage_plan.ahk)を参照してください。

## 弾幕入力の流れ

[入力コントローラー](../../src/input/input_controller.ahk)は動画と入力欄を確認してから文字を入力します。検索・アドレス欄や識別できない対象には入力しません。IMEは入力前にオフにし、そのまま保持します。制御文字を含む本文は、保存値を変更せず入力を拒否します。

[ショートカットキュー](../../src/shortcuts/shortcut_queue.ahk)は通常キーを離した順に操作を保持します。押しっぱなしを連発扱いにしません。停止は押下時に処理し、後続を破棄します。操作中のジョブ・通信は待機理由で、対象変更や操作失敗はキューの破棄理由です。

対象はウィンドウ・動画・セッションで固定します。弾幕の割当を受付時に保存し、入力直前にID・本文・対象を再確認します。フォーカス確認は一度だけ消費します。フォーカス移動は最大350ms待ち、クリアは同じ入力欄か確認してから削除キーを送ります。

送信操作は現在のチャット欄を確認し、Enterを1回送ります。自動フォーカスや結果不明時の再送は行いません。検査とOS入力は不可分ではなく、外部アプリのフォーカス変更までは防げません。YouTube側の受理も確認しません。

## 登録の検出・確定・同期

[リアクションコントローラー](../../src/reactions/reaction_controller.ahk)はジョブ所有者を明示して、登録・確認・送信を進めます。後継ジョブへ切り替わったら古い処理は操作しません。

ボタン登録はブラウザー種別ごとに5種類を識別します。保存前の中止は以前の登録を維持し、保存後の中止は確定済み登録を取り消しません。ワーカー同期に失敗してもDBは保持し、次の操作で再同期します。失敗した送信を自動再実行しません。

送信直前にも動画、ウィンドウ、前面とボタンを確認します。InvokeなどのUIA操作手段を使い、`LegacyIAccessiblePattern`も現行ブラウザーで利用する手段として残しています。「操作済み」はボタン操作の完了数で、サーバーの受理数ではありません。

## ワーカー通信と資源解放

[worker_client.ahk](../../src/browser/worker_client.ahk)はローカル名前付きパイプで通信します。4バイト長とUTF-8の`key=value`を使い、最大32768バイトです。応答の連番、ウィンドウ、プロセスを照合します。入力確認は2.5秒、その他の要求は8秒でタイムアウトします。

ワーカーのSignal・Process・Pipeハンドルは一つの所有者が管理します。終了には作成時のProcessハンドルを使い、再利用されたPIDを終了しません。パイプを閉じて250ms待ち、必要なら終了を要求して2秒待ちます。終了を確認できなければハンドルを保持して失敗を通知し、再試行できる状態を残します。通信失敗と終了失敗が重なった場合は両方を保持します。

## キャッシュと画面更新

アドレス欄のキャッシュはUIA要素の所属を再確認し、現在の値を読みます。URLをキャッシュしません。最大16ウィンドウ分を保持します。リアクション要素も動画・ウィンドウ・providerの変化で無効化し、操作時に再確認します。

画面は部品を準備してから表示します。作業領域へ収まるよう配置し、構築・表示失敗では未公開画面を破棄して所有権を戻します。親の有効状態は実際の状態を記録して復旧し、他の所有者が無効化した画面を有効にしません。

`RefreshCycle`は再入した更新要求をまとめます。一覧とドロップダウンの選択は行番号ではなくIDで復元し、失敗時も再描画を戻します。管理一覧は一つの不変な表示モデルとネイティブの仮想一覧を使います。パレットは全件を検索し、表示だけを500件に制限します。

## 初期化・バックアップ

新規DBは一時ファイルへ作成し、検証・終了後に正式名へ移します。既存の不正・未対応DBを黙って初期化しません。復旧時は利用者の確認後にDBと付随ファイルを退避します。部分失敗では移動を戻し、戻せない場所とエラーも通知します。[利用者の復旧手順](../user/maintenance.md)を参照してください。

### JSON交換形式2

[JSON入出力](../../src/settings/user_data_json.ahk)はDBと独立した交換形式2だけを扱います。形式1を補完・正規化しません。

| オブジェクト | 必須項目 |
|---|---|
| ルート | `format: "ChatPalette"`、`version: 2`、`profiles`、`sharedItems`、`preferences`、`reactionRegistrations` |
| 配信者 | `id`、`name`、`channel`（未連携は空文字）、順序付きの`items` |
| 弾幕 | `id`、`name`、`text`、整数の`slot`（0・1・2） |
| 共通設定 | `inputProfileId`、整数の`autoMode`（0・1）、`reactionKind`、`reactionCount`、`reactionIntervalMs`、`shortcutKeys` |
| キー | `chat_send`を含む全11操作の文字列。任意操作の未割当は空文字 |
| ボタン登録 | 小文字の`browser`、5種類の`tokens`。各tokenの`name`・`id`・`class`・`type`を検証 |

登録情報の追加項目は保持します。それ以外の未知項目、必須項目の欠落、型違いを拒否します。全階層で大文字小文字を無視した重複キーを拒否し、数値文字列や小数を整数へ変換しません。厳密なUTF-8、正しいサロゲートペア、通常のエスケープ、UTF-8 BOMを受け入れ、不正UTF-8・NUL・単独サロゲートを拒否します。上限は128MiBです。

入力は検証用のメモリDBで件数・値・外部キー・ID・スロットを検査します。読取元を変更せず、検証済みの値だけを稼働DBへ全件置換します。取り込み前にはJSONバックアップを作り、キー登録とDB保存の失敗に備えます。成功後に履歴を消去して画面を更新し、確定後の画面更新失敗を保存失敗と区別します。

出力はBOMなしUTF-8の一時JSONへ書き、同じ読込経路で全対象値を照合してから正式名へ移します。既存ファイルを上書きしません。復元時にJSONを`settings.db`へ直接配置しません。
