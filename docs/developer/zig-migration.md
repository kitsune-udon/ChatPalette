# Zig全面移行計画

対象はChatPalette 0.8.0（`v0.8.0`、`b85df1c`）。チェックは各段階の検証者が完了を確認したときに付ける。[独立レビューと対応記録](zig-migration-review.md) · [実装と基準値の検証記録](zig-migration-evidence.md)

## 到達点と根拠

利用者はWindows 11 x64でZIPを空のフォルダーへ展開し、`ChatPalette.exe` から起動する。起動、常駐、設定、画面、キー入力、ブラウザー操作をすべてZigで実装する。開発側もビルド、検査、計測、配布検証を `zig build` から実行できるようにし、Windows Sandboxのゲスト側を含め、現役の手書きAHK・PowerShell・試作用Cブリッジを退役させる。WindowsのWin32、UI Automation（UIA）、COM、システムの `winsqlite3.dll` とSDK由来の宣言は引き続き使用する。参照用の0.8.0はタグと検証済み配布物で保存する。

ワークスペースの `prototype/zig-worker/measurements.json` では、Braveの8条件・192組で2種類の要求が期待値と一致した。公開動画の初回判定中央値はPowerShell 540.3 ms、Zig 63.5 ms。公開ページの動画判定と文書本体の拒否、ローカルHTMLでのチャット・コメントの肯定例を区別する。他の要求、実ライブの入力・リアクション、アプリ全体の起動性能は今後の検証対象となる。最初にワーカーを交換し、保存形式を保ったまま本体を段階的に組み上げる。

### 実装の境界

Windows 11 x64は今回の初回配布・検証範囲として選んだ。0.8.0はWindows標準SQLiteとJSON関数を要件としており、Windows 10各版・32bit・ARMの互換性は未検証。同一EXEの2プロセス構成も今回の設計案である。[現行の動作環境](../../README.md#必要な環境)

| 所有者 | 移す責務 |
|---|---|
| 常駐する本体 | Win32メッセージループ、トレイ、ウィンドウ、キーの受付、入力、設定DB、編集下書き・Undo、ジョブと停止。UIスレッドはワーカー待ちでも停止・画面イベントを処理する。 |
| 別プロセスのワーカー | 同じEXEを内部ワーカーモードで起動し、専用COMスレッドでUIAを扱う。動画のoEmbed取得とキャッシュを所有する。DBへの書き込みは本体に集約する。 |
| 開発・検証ツール | 旧版を振る舞いの比較対象に固定する。新旧へ同じ入力を与えて期待値と照合し、実OSやGUIでしか確認できない条件はWindows上で測る。 |

同じEXEの役割を引数で先に決め、ワーカー起動が本体の多重起動制御・DB初期化・キー登録へ入ることを防ぐ。移行中の試作ワーカーは専用EXEのまま旧本体へ明示指定し、アプリを起動するたびに使用実装を一つ選ぶ。送信中の自動切替や要求の再実行は行わない。[現行の状態所有と通信契約](architecture.md)

## マイルストーン

各段階の担当は役割で示す。実装担当が成果物・候補コミット・実行環境・成功と失敗の記録を揃え、担当外の検証者が完了条件を確認した時点でチェックする。M0を起点に、ワーカー（M1）と保存（M2）は並行できる。両方が揃うと本体（M3）と画面（M4）を通して試せる。検証基盤（M5）はM0直後から移植し、M4の結果を統合して閉じる。M5で旧経路を外して候補を固定し、M6で更新と切り戻しを試す。M7で同じZIPを正式配布する。日程と人員は未確定。M0の対応表とM1・M2の実績を基に見積もりを更新する。

- **旧本体との接続**　0.8.0の起動先は `powershell.exe -File` に固定されている。隔離した旧本体に、指定されたZig EXEを絶対パスと `-PipeName` 引数で直接起動する最小の差分を用意する。従来の起動を既定とし、作成したプロセスとパイプ接続元のPIDが一致することを両構成で確認する。[旧本体のワーカー起動処理](../../src/browser/worker_client.ahk)
- **完了条件**　移行用AHK本体から全10要求を製品のパイプで実行する。応答連番・HWND・接続元PID、32 KiB上限、確認2.5秒・その他8秒、切断後の終了・再起動を検査する。拒否、タイムアウト、古いフォーカス証明、タブ変更、UIA要素の差し替えを注入する。別々に初期化したローカル画面に5ボタンと入力イベントの記録を設け、指定ボタンの成功は正確に1回で `operated`、確認・拒否・ホバーは0回、実行直後の応答喪失は `unknown` で再送0回となることを確かめる。
- **境界事例**　たとえば `https://www.youtube.com/a/../watch?v=ZigTest0001` は現行のURI解析が正規化し、試作は拒否する。旧版で採取した期待値をM0に固定し、M1で正規化後の動画ID・対象外ホストの拒否を再現する。oEmbed失敗・オフライン・キャッシュ期限と、取得中に動画が変わる場合も試す。登録やフォーカスを持つワーカーを一連の操作の途中で替えない。
- **切り戻し**　ジョブを止め、旧本体とワーカーを終了して旧構成を再起動する。DBの確定済み登録を読み直す。

### M2　保存・交換・ライブラリを移す

- [x] **M2完了**　保存とライブラリの独立検証、0.8.0とのDB5・JSON2双方向往復、境界と故障注入を確認した。キーと画面の統合確認はM3・M4で行う。[検証記録](zig-migration-evidence.md#zig実装の検証)
- **成果物**　アプリ直下の `data/settings.db`、DB5・JSON2、検証・バックアップ・復旧、共通／配信者別の弾幕・チャンネル・割当・編集履歴を扱うZigモジュール。DB確定後にライブ状態を公開し、別接続の更新をロック取得後の `data_version` 照合で検出する。
- **完了条件**　独立した合成コピーで旧→新→旧と新→旧→新のDB・JSONを往復する。DBの `application_id=1129335892` と `user_version=5`、JSON形式2、IDの大小文字、順序・スロット、登録の追加項目を照合する。配信者1万件、弾幕合計10万件、絵文字を含むUTF-16換算32 MiB、DB・JSON各128 MiB、登録1件8,192バイト（UTF-8終端込み）・合計24,000バイトの各境界を試す。形式違い・破損・不正UTF-8・重複キーを拒否する。競合や空き容量不足で未確定の値を公開しない。新規DB作成と出力JSONは一時ファイルを検証してから確定する。
- **故障時の観測**　全件取込前の自動JSONバックアップに失敗すれば変更前で止める。確定前の失敗ではDBと公開済み設定を以前の値に保ち、OSのキー割当の復元を試みる。確定後の描画失敗では保存済みと通知する（キーと画面の実観測はM3・M4）。Undoは直近30件をメモリに保持し、取込成功時に消去する。WALだけに未対応版が確定したDBも拒否し、元DBと既存WALの内容を照合する。SQLiteが読み取り時に作る空の付随ファイルは区別する。復旧でDB・`-journal`・`-wal`・`-shm`の退避が途中で止まれば逆順に戻す。巻き戻しにも失敗した場合は初期化せず、残った場所と理由を表示する。[形式と原本保全の検査](../../tests/test-supported-formats.ps1)
- **切り戻し**　この段階は合成データ専用。失敗コピーとログを保持して、旧版から再現する。[保存と復旧の利用手順](../user/maintenance.md)

### M3　常駐本体・キー・入力と停止を統合する

- [x] **M3完了**　通常ビルドの21件、起動3モードの同一展開先での交替、入力・保存・ワーカーの故障時の復旧を確認した。[検証記録](zig-migration-evidence.md#m3の完了判定)
- **成果物**　通常起動・`--smoke`・`--quiet`、単一起動、トレイ、終了と再起動、キー登録とロールバック、入力対象と編集対象の分離、ページ操作とリアクションジョブを持つ本体。通常キーは解放順に受け付け、停止は押下時に割り込む。Win32の押下通知だけで実装を閉じず、キー解放と受付条件を組み合わせる。
- **起動と終了の互換性**　同じ展開先では通常・quiet・smokeの再起動が前の本体を置き換え、別フォルダーと内部ワーカーは別扱いにする。旧本体と子が終了しキーを解放してから新本体が引き継ぐ。未知・余分な引数の拒否はDB初期化前、静的ビルド検査は稼働中の本体に影響しないことを確かめる。パイプを閉じて250 ms待ち、必要なら作成時のプロセスハンドルで終了を要求して2秒待つ。終了不明なら所有権を保持し、通信と後始末の両方の失敗を観測する。[起動の回帰検査](../../tests/test-startup.ps1)
- **完了条件**　11操作の連続・長押し・停止、修飾キーを保持した操作、IMEオフでの弾幕入力、明示送信のEnter 1回、途中の別窓・別動画、通信中の停止と後継ジョブを試す。登録・DB確定・ワーカー同期の各境界に故障を入れ、復旧または再同期を確認する。保存失敗時は変更したキーすべての解除・再登録を試す。復元にも失敗したときは、DBと公開済み設定を旧値に保ち、元の原因とすべての復元エラー、再起動の案内を示す。[キー復旧の回帰検査](../../tests/test-shortcut-bindings.ps1)
- **操作単位の観測**　弾幕入力後はIMEオフ・Enter 0回、明示送信は現在のチャットへEnter 1回、クリアは同一チャットの確認後、表示操作はホバーだけとする。パレットの3秒待機とキー実行の即時開始、ランダムの毎回選択、開始間隔と直列実行を検査する。中断のないN回の指示は指定先に正確にN回届く。停止時は発行済みの応答を待ち、成功した分を計上し、後続は0回。通信切断で結果不明なら再送せず、古いジョブが後継の進捗・結果を書き換えない。成功回数はUIA操作完了を数える。[利用者の操作と間隔](../user/reactions.md)
- **切り戻し**　隔離した候補本体を終了し、子プロセスとキー登録の解放を観測してから旧本体を起動する。旧版と候補版を同じ操作先・データで同時に常駐させない。

- **完了条件**　M5で旧経路を外したクリーンチェックアウトからビルド・全検査・梱包できた証拠を確認する。公開にはM6合格済みのZIPをそのまま使い、タグのコミット、添付名・サイズ・SHA-256を検証記録と照合する。更新前版の配布物と復旧手順を取得できることも確認する。候補コミット、入力、ZIPのいずれかが変われば新候補としてM5に戻し、変更の影響を受けるM6の試験と配布物の同一性を再検証する。公開の判断と実行はリリース時に行う。

## 検証の進め方

M0〜M2の完了判断には固定した旧版と当時の検証記録を使う。M3以降は、各段階の完了条件に対して既存の試験記録を照合し、必要な観測がそろった項目はその場で合格を記録して先へ進む。一つの試験で複数の契約を確認できる場合は、同じ記録を参照する。追加試験・修正は、完了判定に必要な観測の不足と、完了条件を満たさなかった項目に限る。試験環境が用意できない項目は、欠けている環境と試験を記録し、実行可能な必須項目を進める。[0.8.0の57群との照合](zig-migration-evidence.md#080の57群との照合)

| 作業順 | 今残っている作業と判定に必要な証拠 |
|---|---|
| M3の入力と常駐 | 完了。通常ビルドと故障注入の記録は、旧版の個別契約を照合するM5でも参照する。 |
| M4の利用者操作 | 完了。通し操作、0.8.0との縮小画面・キー操作、100%と150%の画面間移動、件数別の実測、診断を確認した。残っている描画故障の変種と長文10万件での終了時間切れは、M5で対応する旧版契約の判定に使う。 |
| M5の照合と固定 | M3・M4と並行して57群の証拠を対応付け、未実行・失敗が残る条件を埋める。固定コミットではソース、EXE、ZIPと自動検査を照合できた。現役の起動・ビルド・試験・ゲスト・配布入口での旧依存と、旧版独自の故障を引き続き照合する。作業中の個別修正は `zig build check` の該当群で検証する。 |
| M6の実環境と復旧 | 固定したZIPのクリーン展開と0.8.0への切り戻しが成功した。Braveは両画面のフォーカスと5ボタンの表示、通常ページの登録、実チャンネルの取得と自動選択を確認した。「送らずに確認」は通常ページと最大化した別窓での合格記録を使う。完了条件に関係する実機差は、同条件の0.8.0で再現を試す。Braveの別窓での登録と入力欄の識別・拒否の不足分、Firefoxの通常ページ・別窓での必須比較を進める。 |
| M7の正式配布 | M6の合格記録から同じZIPを選び、公開判断後にタグと配布物を公開する。取得し直した添付物の名前・サイズ・SHA-256、タグのコミット、旧版の配布物と復旧手順を照合して閉じる。 |

合成ブラウザー回帰はオフラインSandboxで実施し、起動IDと終了後の一覧を照合してから次の試験を起動する。対話デスクトップを共有する試験は時間を分ける。保存や性能の変更を検証するときは、同じデータ、計測範囲、反復条件で比較し、元の結果と生値を残す。[検証ガイド](testing.md#試験環境を選ぶ)

## 判断に使う証拠

移行責任者は、機能差、障害時の状態、性能を別々に判定する。性能は同一機材・同一データ・交互順で中央値と最大値、失敗と生値を残し、初回と後続、成功と拒否を分ける。性能改善で機能差を相殺しない。既存の時刻制約と操作順を満たし、旧版と再現可能な性能差があれば、切替前に原因・利用者への影響・再測定結果を記録する。[検証方法](testing.md)・[既存の性能記録](complexity-results.md)
