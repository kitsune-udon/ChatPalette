# Zig全面移行計画の独立レビュー

2026年11月18日。計画の執筆者とは別の3担当が、0.8.0のコード・テスト・配布記録とワーカー試作を参照して草案を点検した。担当は「データ・復旧」「Windows・ブラウザー」「検証・配布」。複数担当が見つけた同じ問題は1行にまとめた。判定対象は[移行計画](zig-migration.md)である。

| 指摘元 | 草案のまま進めた場合の問題 | 計画に反映した対応 |
|---|---|---|
| 3担当共通 | 旧本体はPowerShellに `-File` を渡す。ラッパーがZigを起動すると、所有するPIDとパイプ接続元が異なる。 | M1に、隔離した旧本体がZigを直接起動する最小差分を追加。指定は起動時に固定し、製品のPID・連番・HWND検査を通す。 |
| Windows・ブラウザー | 試作の192組には、旧版が正規化するドットセグメント付きURLが含まれない。 | M0で既知差の入力と旧版の期待値を固定し、M1に互換試験を追加。Windows 11 x64と同一EXEの別プロセス構成は今回の設計条件と明記。 |
| データ・復旧 | DB退避の巻き戻しまで失敗することがある。保存前と確定後の表示失敗も結果が異なる。 | M2でWAL内の確定値、付随ファイル、戻せない場所の通知、取込前の自動バックアップ、確定後の「保存済み」通知を検査。M3・M4でキー・画面まで再観測する。 |
| データ・復旧 | 件数や登録サイズの境界、メモリ上のUndoをDB互換と混同しやすい。 | M2に配信者・弾幕・登録の個別／合計上限と文字コードの単位、Undoの30件と取込後の消去を追加。 |
| データ・復旧（再レビュー） | 保存失敗時に、OSのキー割当の復元まで必ず成功するという完了条件は、既存の複合故障試験で満たせない。 | M2・M3を修正。全件の解除・復元を試み、失敗時もDBと公開済み設定を旧値に保ち、元の失敗・全復元エラー・再起動案内を観測する。 |
| Windows・ブラウザー、データ・復旧 | 単一起動のチェックだけでは同一パスの置き換えを保証できず、子の終了失敗で別プロセスを巻き込む余地がある。 | M3で同じ展開先、別展開先、内部ワーカー、静的検査を区別。終了を確認できない場合は作成時のハンドルを保持し、失敗した後始末を記録する。 |
| Windows・ブラウザー、データ・復旧 | 「規定回数以下」なら送信ゼロでも合格する。停止と応答喪失でも成功回数の扱いが違う。 | M1・M3で5ボタンと入力イベントを観測。正例は正確に指定回数、拒否・確認はゼロ。停止時は発行済みの応答を計上し、結果不明時は再送ゼロとする。 |
| Windows・ブラウザー | 5ボタンの登録成功だけでは、製品のキーによるフォーカス移動やメニュー表示を証明できない。 | M6でBraveとFirefoxの実ページ、別窓、実入力欄を操作。ホバーの応答と5種類の可視化を別に記録し、6種類のブラウザー名認識と区別する。 |
| 検証・配布 | 「57群を追跡」だけでは未実行・既知失敗を合格にできる。共通故障注入関数の利用数だけでは直接置換を取りこぼす。 | M0・M5で旧結果・個々の期待値・新しい成功／故障観測を紐付ける。57群を段階へ割り当て、先頭の区分32／25を再集計。直接置換と未解決失敗の扱いも追加。 |
| 検証・配布、データ・復旧 | AHKなしの実行と旧版への切り戻しを一つの環境で試すと前提が衝突する。起動のみの試験では遅れてロードされる依存を見落とす。 | M6でクリーン配布環境、オンライン実機、旧版＋AHKの復旧環境を分ける。ワーカー・DB保存・診断・再起動まで子プロセスとロードDLLを観測する。 |
| 検証・配布、データ・復旧 | 検証後に版番号・文書・旧コードを変更すれば、同じZIPを昇格できない。試作ソースも0.8.0のタグには含まれない。 | M0で旧ZIPと試作EXEのハッシュを照合し、試作ソースの固定を着手項目にした。M5で退役と同梱内容を確定し、M6は同じZIPを検査、M7はそのまま昇格。変更時は候補を作り直す。 |
| 検証・配布（再レビュー） | 全体の順序と本文の切替時期が食い違い、開発ツールやSandboxゲストから起動される旧スクリプトも退役確認から漏れ得る。 | 概要をM5固定・M6試験・M7配布に統一。M5でビルド依存関係、ゲストの起動コマンド、実行記録、配布許可リストまで照合する。 |

主要な照合先は、[ワーカー起動と寿命](../../src/browser/worker_client.ahk)、[起動の回帰検査](../../tests/test-startup.ps1)、[未対応形式の保全検査](../../tests/test-supported-formats.ps1)、[入力検査の直接置換](../../tests/test-input.ps1)、[ブラウザーの検証範囲](testing.md#実ブラウザーを確認する)、[配布の同一性検証](guide.md#リリース手順)。

## 再レビュー結果

3担当が修正後の担当箇所を読み直した。データ・復旧担当は複合故障時のキー復旧、検証・配布担当はM5〜M7の順序と旧実行経路の退役確認について追加修正を求め、両担当が最終文で解消を確認した。Windows・ブラウザー担当も、起動・副作用・実画面の指摘が完了条件に反映されたことを確認した。計画の未解決指摘は0件。

実装の確認はM0以降に行う。特に、Firefoxと実ライブでの互換性、DBを更新してからの旧版復帰、Zigだけで検証・梱包したZIPの動作には、各段階で新たな証拠が必要になる。
