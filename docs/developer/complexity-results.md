# 複雑度整理の検証記録

このページは変更時点の計測・検証記録です。記載したDB形式やテスト群数は当時の値であり、現在の仕様・手順は[設計](architecture.md)と[検証ガイド](testing.md)を参照してください。

## 変更範囲

- デスクトップ入口からモジュール一覧と初期化を分離し、隔離テストも同じ初期化を利用。
- 通常の外部処理は`RuntimePorts`で差し替え、AHKの関数名・本体を書き換える検査を削減。
- 入力・編集の選択を独立したIDで保持し、一覧の選択復元もIDを使用。
- ライブラリの保存・公開とワーカー資源の所有を集約。
- リアクションジョブの項目、進行状態、終了処理を統一。保存と同期は別々に記録。
- 保存の編集・追加・削除別の高速化分岐を、共通の変更範囲計算に置換。

DB形式と利用者の保存場所は変更していません。

## 保存計画の計測

2026-09-23、Windows build 26200、AutoHotkey 2.0.28（64bit）、Windows PowerShell 5.1.26100.9444。当時の`benchmark-storage.ps1`で比較元（`b7dafb0`）と変更後を比較しました。合成データの各条件でウォームアップ1回、その後7回を計測しています。

| 件数 | 操作 | 変更前の中央値（ms） | 変更後の中央値（ms） | 変更後の最大値（ms） |
|---:|---|---:|---:|---:|
| 1,000 | 編集 | 0.459 | 0.616 | 0.669 |
| 1,000 | 隣接交換 | 0.474 | 0.582 | 0.625 |
| 1,000 | Undo | 0.464 | 0.589 | 0.656 |
| 10,000 | 編集 | 4.397 | 5.532 | 5.924 |
| 10,000 | 隣接交換 | 4.416 | 6.041 | 6.105 |
| 10,000 | Undo | 4.322 | 5.343 | 5.808 |
| 100,000 | 編集 | 51.522 | 58.761 | 59.491 |
| 100,000 | 隣接交換 | 51.214 | 58.957 | 61.195 |
| 100,000 | Undo | 48.593 | 56.131 | 57.696 |

変更後には計算時間の増加があります。10万件で中央値の増加は約7〜8msです。変更前に比べて高速になったという結果ではありません。編集・追加・削除で異なるアルゴリズムを保守する代わりに、変更範囲を同じ処理へ通す構成を採用しました。

変更された所属先を毎回全件計算する案も試しましたが、10万件の編集で中央値1,562.5msとなったため採用していません。現在の実装は未変更の先頭・末尾と保存行を再利用し、順序値の間隔が足りない場合だけ全体へ範囲を広げます。

これは保存計画だけの測定です。DB書き込み・画面描画・ブラウザー操作の時間を含まず、任意のデータ分布で同じ時間を保証しません。ランダムな多数箇所の同時変更や大規模な逆順操作では、変更範囲が広がります。

## プロジェクト全体の最適化（2026-09-23）

- パレットの有効状態・プレビューと取り消しボタンの文言は、同値ならコントロールへの書き込みを省略。別の状態キャッシュは追加していません。
- 非表示タブでは有効状態の取得値とAHKが保持する意図した状態が異なるため、管理画面の有効状態への代入は維持しました。
- 表示モデルの選択位置と配信者実体の重複探索、管理画面の不要な部品配列と順序変更後の二重更新を削除。
- テスト実行は直下の`test-*.ps1`を名前順に自動検出。手動の実行一覧を廃止し、実行中のファイル名と完了件数を表示します。

性能回帰テスト105項目が成功しました。状態を変えずに20回更新しても、対象のパレット部品と文言への書き込みは0回で、処理開始・終了時には必要な更新が行われます。これは不要な処理回数の検証であり、アプリ全体の実時間の高速化率を測定した結果ではありません。自動検出へ変更した一括実行も、全28テスト群が成功しました。

## 編集下書きの複製削減（2026-09-25）

Windows build 26200、AutoHotkey 2.0.28（64bit）、Windows PowerShell 5.1.26100.9444で比較しました。比較元は同日の検証済み配布物の`library_service.ahk`で、同じ現行ソースの隔離コピーへ、このファイルだけを差し替えています。比較する差分が今回の複製範囲変更だけであることも確認しました。
