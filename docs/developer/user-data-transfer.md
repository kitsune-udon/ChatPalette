# ユーザーデータ移行の実装記録

2026-09-27。利用者のインポート・エクスポート要望と、交換形式をJSONにする指定への対応記録。

## 方針と根拠

利用者が内容を確認して持ち運べるよう、交換ファイルと取り込み前の自動バックアップにはUTF-8のJSONを使う。内部保存はSQLiteのままにし、全件置換・キー復旧・競合検出を再利用する。個別マージと旧形式の変換は範囲外。従来のDBバックアップは引き続き手動で復元できる。

保存対象は配信者・共通および配信者別の弾幕・ID・順序・スロット・チャンネル連携・選択中配信者・自動判別・リアクション初期値・全キー・ボタン登録。取り消し履歴は成功時に消去する。入力元のDB構造を移植せず、検証済みの値だけを既存DBへ一つのトランザクションで書く。

## 受け入れ条件とレビュー

実装前レビューでJSONへの変更を承認。必須確認事項は、交換形式の厳密な項目・型・重複検証、UTF-8とサロゲート、登録ブラウザーの正規表記・重複、既存登録の追加項目の保持、保存先の競合、確定後の画面更新失敗の区別、自動退避・キー登録・DB保存失敗の保護。

JSONは読み取りのみで開き、Windowsの厳密UTF-8変換と既存SQLite JSON関数で解釈する。検証専用のインメモリDBで既存の件数・値・外部キー・ID・スロット制約を検査し、検証前に稼働DBを変更しない。登録情報の追加フィールドは保持する。全文から各弾幕を繰り返し抽出せず、配信者・弾幕の局所オブジェクトを解釈する。

出力はインデント付きUTF-8（BOMなし）。128MiBの上限を設け、JSONエスケープでサイズが増えた場合も公開前に確認する。一時ファイルへ書き、同じインポート経路で読み戻して全対象値を照合してから正式名へ移す。上書きはしない。確認後は既存データのJSONバックアップを作り、キー登録とDB確定を既存のキー復旧処理でまとめる。確定までは保存済み比較基準とライブ状態を公開しない。操作中は編集・入力・ブラウザー処理・重複移行を拒否する。

## JSON交換形式1

ルートは `format: "ChatPalette"`、`version: 1`、`profiles`、`sharedItems`、`preferences`、`reactionRegistrations`。内部DBの形式番号とは独立する。

- `profiles` は順序付き配信者配列。各要素は `id`、`name`、`channel`（未連携は空文字）、`items`。
- 共通および配信者別の弾幕は順序付き配列。各要素は `id`、`name`、`text`、整数の `slot`（0・1・2）。
- `preferences` は `inputProfileId`（未選択は空文字）、整数の `autoMode`（0・1）、`reactionKind`、`reactionCount`、`reactionIntervalMs`、全10操作の文字列を持つ `shortcutKeys` オブジェクト。
- `reactionRegistrations` は登録情報の配列。`browser` と5種類の `tokens` を既存制約で検証する。ブラウザー名は小文字で重複不可。既存の追加項目は保持する。

登録情報以外の項目名は上記に限定し、欠落・余分な項目・型違いを拒否する。全階層で大文字小文字を無視した重複キーを拒否する。数値文字列や小数表記を整数として自動変換しない。UTF-8 BOM、正しいサロゲートペア、通常のJSONエスケープは受け入れ、不正UTF-8・単独サロゲート・NULを拒否する。

受け入れには全対象値の往復一致、失敗時のデータとライブ状態の保持、実GUI部品の更新、関連回帰検査の成功、サブエージェントによる結果レビューが必要。
