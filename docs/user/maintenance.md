# 保守とトラブル対処

[文書一覧](../index.md) · [保存範囲](reference.md#保存されるもの)

設定を読み込めない場合も、DBと付随ファイルを削除しないでください。まず退避し、その形式に対応するアプリで復元します。

## 症状から確認する

| 症状 | 確認・対処 |
|---|---|
| 起動しない | AHK v2、`main.ahk`・`VERSION`・`src/`一式、書込権限、表示されたエラーを確認 |
| パレット・キーが反応しない | トレイから開き、現在のキー・未保存変更・重複を確認。ブラウザー操作はYouTubeを最前面にする |
| 更新が反映されない | 更新先の`main.ahk`を起動し、診断の版・起動日時を確認 |
| 弾幕が出ない | 入力対象・チャンネル連携・検索・弾幕の保存先を確認。手動選択も試す |
| 入力欄が見つからない・複数ある | 入力可能なチャット・コメント・返信欄をクリックし、動画を変えずに入力をやり直す |
| フォーカス移動を確認できない | 入力欄をクリックして再試行。再発時は操作名・結果・ブラウザーを記録 |
| 弾幕キーで入力できない | 通常キーを離して押し直し、管理画面の弾幕割当と入力配信者を確認 |
| ボタンが未登録・識別できない | [登録手順](reactions.md#初回だけ行うボタンの設定)で5種類を表示し、「② 送らずに確認」。不足・重複は実行結果で確認 |
| 動画・操作先が変わった | 対象へ戻り、改めて開始。処理中に画面を切り替えない |
| 操作結果が不明 | 実画面と実行結果を確認。実行済みの可能性があり、自動再送しない |
| 指定間隔より遅い | [間隔の定義](reactions.md#間隔と回数の読み方)を確認し、種類・指定間隔・平均開始間隔を記録 |
| 登録同期に失敗 | 詳細を確認し、次の操作で再同期。繰り返す場合は再起動。登録はDBに残る |
| 保存できない | 権限・読み取り専用・空き容量を確認。別接続の変更なら再起動して読み直す |

編集画面や実行中の処理が操作を制限する場合もあります。閉じるか停止してから試してください。

## 更新を反映する

**対応する保存形式はDB5・JSON2だけです。DB4・JSON1の読込と自動移行は廃止しました。** 旧データは対応する旧アプリと一緒に保管します。旧形式から使い始める場合は空のフォルダーで新規開始し、必要な内容を再設定してください。形式番号を手作業で変更しないでください。

同じ形式の版へ更新する手順です。

1. 編集を保存して処理を終え、[バックアップ](#バックアップする)を取得します。
2. アプリを[終了](reference.md#終了の違い)します。
3. 新しい配布物を空のフォルダーへ展開します。上書きでは廃止ファイルが残る場合があります。
4. 正常終了した旧アプリの`data/`全体を、新しい`main.ahk`と同じ階層へコピーします。
5. 起動して版、弾幕、配信者、キーを確認します。起動できない場合は[復旧](#設定を読み込めないとき)へ進みます。

旧版へ戻すときは旧アプリと更新前のデータを一緒に復元します。正常に更新できてもバックアップは保管してください。

同じフォルダーのソースを変更すると、診断に「更新あり：再起動で反映」と表示します。「アプリを再起動」は現在のフォルダーを開き直し、別フォルダーの新版へ切り替えません。再起動で検索・Undoなどの一時状態は失われます。画面で保存したキー変更には再起動が不要です。

### 設定データの扱い

| 状態 | 起動時の扱い |
|---|---|
| DBなし | 空のライブラリと標準設定でDB5を作成 |
| 正常なDB5 | 保存済みの値を読み込む |
| 空・破損・未対応形式 | 自動初期化せず、復旧画面を表示 |

## バックアップする

編集と処理を終え、「管理・ヘルプ」またはトレイの「ユーザーデータをエクスポート…」を選びます。アプリのフォルダー外に、まだ存在しない`.json`名を指定してください。拡張子を省略すると補います。既存ファイルを上書きしません。

弾幕・配信者・連携・標準設定・キー・ボタン登録を保存します。手動コピーでは正常終了後の`data/`全体をコピーしてください。起動中にDB本体だけをコピーしません。

異常終了後の`-journal`・`-wal`・`-shm`は単独で削除しません。まず通常起動・正常終了を試し、起動できなければフォルダー全体を退避します。

## バックアップから復元する

### アプリからインポートする

1. 編集画面を閉じ、処理を終えます。
2. 「ユーザーデータをインポート…」でJSON2のエクスポートを選びます。DBやJSON1は読めません。
3. 件数とファイル名を確認し、「はい」を選びます。**キー・登録を含む全データを置き換えます。追加・統合ではありません。** 0件ならライブラリを空にします。
4. 完了後に弾幕・配信者・キーを確認します。別PC・ブラウザーでは「② 送らずに確認」も実行します。

「いいえ」では変更しません。原本JSONも変更しません。取り込み前の値は`data/settings.db.before-import-日時-識別子.json`へ自動保存し、完了画面に場所を表示します。元へ戻すにはそのJSONをインポートします。検証・バックアップ・キー登録・DB保存に失敗した場合は中止します。

JSONは128MiBまでで、項目・型・値・重複を検証します。手編集で形式番号や必須項目を変更しないでください。JSONを`settings.db`へ直接上書きしません。成功時はUndoを消去し、検索・編集対象・今回のリアクション条件を読み込み直します。

### 起動できない場合に手動で復元する

1. アプリを終了し、現在の`data/`全体を別の場所へ退避します。
2. 正常終了後に取得したバックアップの`data/`全体を戻します。DB単体のバックアップなら、新しい`data/`へ`settings.db`として配置します。
3. その保存形式に対応するアプリで起動し、弾幕・配信者・設定を確認します。
4. 別環境ではリアクションの「② 送らずに確認」を実行します。

退避元の古いジャーナルを復元DBへ混ぜません。動画キャッシュとUndoはバックアップに含まれません。

## 設定を読み込めないとき

| 選択肢 | 結果 |
|---|---|
| 中止 | 初期化せず終了 |
| 再試行 | 修正・復元後に読み直す |
| 無視 | さらに初期化へ同意すると、元DBと付随ファイルを退避して空の設定で起動 |

退避に失敗した場合は初期化しません。部分的な移動は元へ戻します。戻せない場合は場所と理由を表示します。終了してフォルダー全体を保管し、理由を解消してから元へ戻してください。既存ファイルを上書きしません。

未対応形式は対応する旧アプリで開きます。DB形式番号の手編集では更新できません。

## 初期状態へ戻す

終了して`data/`全体を退避し、起動します。弾幕・配信者・設定・登録をすべて初期化します。元のフォルダーは復元用に保管してください。ボタンだけの問題なら再登録し、動画キャッシュだけなら再起動します。

## 調査を依頼する

診断の「最新の状態に更新」を押してからコピーします。操作順、期待と実際の結果、ブラウザー名、入力欄の種類を添えます。リアクションでは種類・回数・間隔と実行結果も記録します。

診断コピーは版・OS・ブラウザー種別・処理状態・時間を含み、弾幕本文・動画URL・配信者名・保存先を含みません。リアクション結果の詳細は別の情報で、ボタン名やエラー本文を含み得ます。共有前に内容を確認し、DB全体を公開しないでください。

クリアの「キーを送りました」は、内容を読み取って空欄を確認した意味ではありません。
