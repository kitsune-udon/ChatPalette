# 保守とトラブル対処

[文書一覧](../index.md) · [保存範囲](reference.md#保存されるもの)

## 症状から確認する

| 症状 | 最初に行うこと | 解決しない場合 |
|---|---|---|
| 起動しない | AutoHotkey v2で開く。`main.ahk`、`VERSION`、`src/`のソース一式を確認 | 書き込み権限・表示されたエラーを確認。DBを削除せず下の復旧手順へ |
| パレットが見つからない | 現在のパレットキー、またはトレイの「ChatPaletteを開く」 | 編集画面が開いていないか確認。実行中なら進捗が表示される |
| 更新した機能が反映されない | [更新手順](#更新を反映する)で更新先の`main.ahk`を起動する | 診断情報のバージョン・起動日時・ソースの状態を確認 |
| キーが反応しない | トレイの「ショートカットを管理」で現在の割当・未保存変更・重複を確認 | ブラウザー用の操作はYouTubeを最前面にする。編集画面や実行中の処理も確認 |
| 入力可能なチャット欄が見つからない | チャットを表示し、ログイン・配信の状態などから入力可能か確認 | 入力欄をクリックして再試行 |
| チャット入力欄が複数ある | 操作したい欄をクリックし、そのまま弾幕キーで入力。フォーカスキーを押し直す必要はない | 手動選択後も入力できなければ、診断の操作名・結果を添えて報告 |
| フォーカス移動を確認できない | 入力欄をクリックし、動画やウィンドウを切り替えずに再試行 | 再発時は診断の結果とブラウザー名を記録 |
| 弾幕キーで入力されない | YouTubeの入力欄をクリックし、キーを離して押し直す | ショートカット管理の下段で弾幕の割当を確認。配信者別の場合は入力配信者も確認 |
| 配信者の弾幕が出ない | 自動判別の結果・チャンネル連携・検索文字列を確認 | 手動選択で対象を選び、弾幕の保存先を確認 |
| チャット・コメントへ入力できない | 入力欄をクリックし、そこからパレットを開き直す | ブラウザー名と診断情報を記録。識別できない入力欄には入力しない仕様 |
| 操作ボタンが未登録 | 「操作・サポート」→「① ボタンを設定…」 | [準備手順](reactions.md#初回だけ行うボタンの設定)へ |
| 登録したメニューが見つからない | ♡に重ね、5種類を表示して「② 送らずに確認」 | 再登録。別アプリへの切り替えでメニューが閉じる点も確認 |
| 5種類を識別できない | 「リアクションの実行結果」で不足・重複情報を確認 | ボタンがすべて表示されている状態でやり直す |
| 動画・操作先が変わった | 対象のYouTubeへ戻り、改めて開始 | 実行中にタブやウィンドウを切り替えない |
| 操作結果が不明 | 実画面と実行結果を確認 | 直前の操作は実行済みの可能性がある。自動再送はしない |
| 指定間隔より遅い | [間隔の定義](reactions.md#間隔と回数の読み方)を確認 | 種類・指定間隔・平均開始間隔・ブラウザーを記録 |
| 登録の同期に失敗 | 現在の処理は停止。次の操作で再同期する | 繰り返す場合は再起動して診断。保存済み登録はDBに残る |
| 設定・登録を保存できない | 保存先の権限、読み取り専用、空き容量を確認 | 別接続で変更されたとの案内なら、再起動して読み直す |

## 更新を反映する

1. 編集を保存し、実行中の処理を終えてから、[バックアップ](#バックアップする)を取得します。
2. ChatPaletteを[終了](reference.md#終了の違い)します。
3. 新しい配布物を**空のフォルダー**へ展開します。既存フォルダーへの上書きでは、廃止されたファイルが残ることがあります。
4. 以前のアプリの `data/` フォルダー全体を、新しいフォルダーの `main.ahk` と同じ階層へ移します。
5. 新しいフォルダーの `main.ahk` を起動し、診断情報のバージョンと、弾幕・配信者・キー設定を確認します。

正常に起動したら、以前のコードだけが残ったフォルダーは削除できます。バックアップは保管してください。起動できない場合は、データを初期化せず[復旧手順](#設定を読み込めないとき)へ進みます。

同じフォルダー内のソースを変更した場合は、診断情報に「更新あり：再起動で反映」と表示されます。編集や実行中の処理を終え、「アプリを再起動」を押します。このボタンは現在のフォルダーを開き直すため、別フォルダーへ展開した配布物には切り替わりません。再起動すると検索・取り消し履歴などの一時状態は失われます。

画面で保存したキー変更はその場で反映され、再起動は不要です。[割当の変更手順](reference.md#ショートカット)で現在のキーを確認してください。

### 設定データの扱い

| 状態 | 起動時の扱い |
|---|---|
| DBなし | 空のライブラリと標準設定で形式3のDBを作成 |
| 正常な形式3のDB | 保存済みの弾幕・配信者・キー・登録情報を読み込む |
| 破損・空・未対応形式のDB | 自動初期化せず、復旧画面を表示 |

バックアップは形式3に対応するChatPaletteで復元してください。コードを更新しても、設定DBの形式が自動変換されることはありません。

## バックアップする

起動中は、タスクトレイの「弾幕・設定をバックアップ」を選び、**アプリのフォルダー外に、まだ存在しないファイル名**を指定します。弾幕・配信者・共通設定・ボタン登録を一緒に保存します。既存のバックアップは上書きしません。

手動でコピーする場合は、アプリを正常終了してから `data/settings.db` をコピーします。起動中にDB本体だけをコピーする方法は使用しないでください。

異常終了後に `settings.db-journal` などが残っている場合は削除せず、まず通常起動・正常終了を試してください。起動できなければ、DBと付随ファイルをまとめて退避してから調査します。

## バックアップから復元する

1. ChatPaletteを終了します。
2. 現在の `data/` フォルダーを別の場所へ退避します。現在のデータに戻すための控えになります。
3. 新しい `data/` フォルダーを作り、バックアップDBを `settings.db` という名前で配置します。
4. 起動し、配信者・弾幕・標準設定を確認します。
5. 別PCや別ブラウザー環境へ復元した場合、リアクションは「② 送らずに確認」で認識を確認します。

退避した古いジャーナルを復元先のDBへ混ぜないでください。動画キャッシュと取り消し履歴はバックアップに含まれません。

## 設定を読み込めないとき

空・破損・未対応形式のDBを検出すると、黙って初期化せず復旧画面を表示します。

| 選択肢 | 結果 |
|---|---|
| 中止 | 読み込めない設定を初期化せず終了 |
| 再試行 | ファイルを修正・復元した後に読み直す |
| 無視 | 次の確認に同意すると、元DB・付随ファイルを日時付きで退避し、空の設定で起動 |

「無視」は単にエラー表示を閉じる操作ではありません。初期化の確認まで進みます。退避に失敗した場合は初期化しません。途中まで移動したファイルは元へ戻します。戻せないファイルがあるときは「退避先 → 元の場所」を表示します。アプリを終了し、フォルダー全体をコピーして保管したうえで、表示されたファイルを元の場所へ戻してください。既存ファイルは上書きしないでください。

DBの保存形式が未対応の場合は、それを扱える版のChatPaletteで開いてください。DB形式番号を手作業で変更しても、互換性は得られません。

## 初期状態へ戻す

アプリを終了し、`data/` フォルダー全体を別の場所へ退避して起動します。配信者・弾幕・標準設定・ボタン登録がすべて初期化されます。元のフォルダーを保管しておけば、復元手順で戻せます。

ボタン登録だけを直したい場合は、初期化せず対象ブラウザーで再登録します。動画情報のキャッシュだけならアプリの再起動で消えます。

## 調査を依頼する

トレイまたは「管理・ヘルプ」から「診断情報」を開きます。次をまとめると、問題を再現しやすくなります。

- 実行した操作と順序、期待した結果、実際の表示。
- ブラウザー名、チャット・コメント・返信のどの欄か。
- 「診断情報」で「最新の状態に更新」を押した後のコピー。
- リアクションの場合は種類・回数・間隔と「リアクションの実行結果」。

診断には直近のページ操作と処理段階も残ります。クリアの「キーを送りました」は、内容を読み取って空欄を確認した意味ではありません。

診断コピーはバージョン、OS、ブラウザー種別、処理状態・所要時間などを含み、弾幕本文・動画URL・配信者名・保存先パスを含みません。一方、「リアクションの実行結果」の詳細にはボタン名やエラーメッセージが含まれ得ます。診断コピーとは別の情報なので、共有前に内容を確認してください。

設定DB全体を診断情報の代わりに公開しないでください。自分の弾幕やチャンネル連携が含まれます。
