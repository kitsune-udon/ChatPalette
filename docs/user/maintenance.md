# 保守とトラブル対処

[はじめに](../../README.md) · [保存範囲](reference.md#保存されるもの)

更新するときは旧版を終了して、アプリと `data/` を一緒に保管します。設定を読み込めないときも、まず `data/` 全体を別の場所にコピーしてください。次に[設定の復旧画面](#設定を読み込めないとき)で対処を選びます。

## 症状から確認する

| 症状 | 確認・対処 |
|---|---|
| 起動しない | Windows 11 x64を使い、ZIPの展開先から `ChatPalette.exe` を実行したか、書き込み権限と表示されたエラーを確認 |
| パレット・キーが反応しない | トレイから開き、現在のキー・未保存変更・重複を確認。ブラウザー操作はYouTubeを最前面にする |
| 更新が反映されない | 更新先の `ChatPalette.exe` を起動し、「診断情報」で版と配布物の状態を確認 |
| 弾幕が出ない | 入力対象・チャンネル連携・検索・弾幕の保存先を確認。手動選択も試す |
| 入力欄が見つからない・複数ある | 入力可能なチャット・コメント・返信欄をクリックし、動画を変えずに入力をやり直す |
| フォーカス移動を確認できない | 入力欄をクリックして再試行。再発時は操作名・結果・ブラウザーを記録 |
| 弾幕キーで入力できない | 通常キーを離して押し直し、管理画面の弾幕割当と入力配信者を確認 |
| ボタンが未登録・識別できない | [登録手順](reactions.md#初回だけ行うボタンの設定)で5種類を表示し、「② 送らずに確認」。不足・重複は実行結果で確認 |
| 動画・操作先が変わった | 対象へ戻り、改めて開始。処理中に画面を切り替えない |
| 操作結果が不明 | 実画面と実行結果を確認。実行済みの可能性があり、自動再送しない |
| 指定間隔より遅い | [間隔の定義](reactions.md#間隔と回数の読み方)を確認し、種類・指定間隔・平均開始間隔を記録 |
| 登録同期に失敗 | 詳細を確認し、次の操作で再同期。繰り返す場合は再起動。登録はDBに残る |
| 保存できない | 権限・読み取り専用・空き容量を確認。別接続の変更なら再起動して読み直す |

編集画面や実行中の処理が操作を制限する場合もあります。閉じるか停止してから試してください。

## 更新を反映する

**0.8.0からは、保存済みの弾幕・配信者・設定を引き継げます。** この版が読み込めるのは設定DBの形式5（DB5）とエクスポートJSONの形式2（JSON2）です。DB4・JSON1をお使いの場合は、対応する旧版とそのデータを保管し、新版を空のフォルダーで起動して必要な内容を登録し直してください。

1. 旧版で編集を保存して処理を終え、[JSONをエクスポート](#バックアップする)します。
2. 旧版の「管理・ヘルプ」または通知領域のメニューから「終了」を選びます。ウィンドウの×を押しただけではアプリは常駐を続けます。
3. 新版の配布ZIPを、旧版とは別の空のフォルダーへ展開します。
4. 正常終了した旧アプリの `data/` 全体を、新しい `ChatPalette.exe` と同じ階層へコピーします。
5. 新しい `ChatPalette.exe` を起動し、診断で版を確認します。弾幕、配信者、キーも確認してください。起動できない場合は[復旧手順](#設定を読み込めないとき)へ進みます。

「診断情報」に「更新あり。再起動で反映」と出た場合は、現在の展開先の実行ファイルが起動後に変わっています。「アプリを再起動」で同じ展開先の `ChatPalette.exe` を開き直せます。検索と取り消し履歴はアプリの終了時に消去されます。

### 0.8.0へ戻す

1. 新版を終了し、新版の `data/` 全体をバックアップします。
2. 0.8.0を別のフォルダーに展開し、新版で保存した `data/` のコピーを置きます。0.8.0の起動にはAutoHotkey v2が必要です。[0.8.0の配布ページ](https://github.com/kitsune-udon/ChatPalette/releases/tag/v0.8.0)
3. 0.8.0を起動し、更新後に編集した弾幕や設定を開けるか確認します。失敗した場合は終了し、更新前に保管した `data/` から復元します。この場合、更新後の変更は別に保管した新版のデータに残ります。

### 設定データの扱い

| 状態 | 起動時の扱い |
|---|---|
| DBなし | 空のライブラリと標準設定でDB5を作成 |
| 正常なDB5 | 保存済みの値を読み込む |
| 空・破損・未対応形式 | 自動初期化せず、復旧画面を表示 |

## バックアップする

| 方法 | 手順 | 戻し方 |
|---|---|---|
| アプリからJSONに書き出す | 編集を保存して処理を終え、「管理・ヘルプ」→「ユーザーデータをエクスポート…」を選びます。アプリのフォルダー外に新しいファイル名を指定します。拡張子を省略すると `.json` が付きます。 | [アプリからインポートする](#アプリからインポートする) |
| データフォルダーをコピーする | アプリを正常終了し、`ChatPalette.exe` の隣の `data/` をフォルダーごと別の場所にコピーします。 | [フォルダーから手動で復元する](#起動できない場合に手動で復元する) |

JSONには弾幕・配信者・連携・標準設定・キー・ボタン登録が入ります。エクスポートには毎回新しいファイル名が必要です。

異常終了後の`-journal`・`-wal`・`-shm`は単独で削除しません。まず通常起動・正常終了を試し、起動できなければフォルダー全体を退避します。

## バックアップから復元する

### アプリからインポートする

1. 編集画面を閉じ、処理を終えます。
2. 「管理・ヘルプ」→「ユーザーデータをインポート…」を選び、書き出しておいたJSON2のファイルを開きます。
3. ファイル名と弾幕・配信者・登録の件数を確認します。**「はい」を押すと、キーとボタン登録を含む全データが、そのファイルの内容に置き換わります。** 弾幕・配信者がともに0件ならライブラリは空になります。「いいえ」を押すと元の状態で戻れます。
4. 完了後に弾幕・配信者・キーを確認します。別PC・ブラウザーでは「② 送らずに確認」も実行します。

取り込み直前の設定は `data/settings.db.before-import-識別子.json` に自動保存されます。取り込みを元に戻すときは、完了画面に表示されたこのJSONをインポートしてください。入力内容の検証、取り込み前のバックアップ、DBへの保存に失敗すると置き換えは中止されます。

取り込みが完了すると、取り消し履歴と検索・編集対象がリセットされます。今回のリアクション条件には取り込んだ標準設定が反映されます。JSONの形式番号や必須項目は書き換えず、復元にはインポートを使ってください。[ファイル・件数の上限](reference.md#上限)

### 起動できない場合に手動で復元する

1. アプリを終了し、現在の `data/` をフォルダーごと別の場所へ移動します。
2. 正常終了後に保管した `data/` のコピーを、復元先の `ChatPalette.exe` の隣に置きます。正常終了後に取得した `settings.db` だけを戻す場合は、空の `data/` を作成してそこに置きます。
3. その保存形式に対応するアプリで起動し、弾幕・配信者・設定を確認します。
4. 別環境ではリアクションの「② 送らずに確認」を実行します。

退避したDBのジャーナルを、別のバックアップのDBと混ぜないでください。動画情報のキャッシュと取り消し履歴はアプリの終了時に消去されます。

## 設定を読み込めないとき

| 選択肢 | 結果 |
|---|---|
| 中止 | 初期化せず終了 |
| 再試行 | 修正・復元後に読み直す |
| 無視 | さらに初期化へ同意すると、元DBと付随ファイルを退避して空の設定で起動 |

退避に失敗した場合は初期化しません。部分的な移動は元へ戻します。戻せない場合は場所と理由を表示します。終了してフォルダー全体を保管し、理由を解消してから元へ戻してください。既存ファイルを上書きしません。

未対応形式は対応する旧アプリで開きます。DB形式番号の手編集では更新できません。

## 初期状態へ戻す

終了して`data/`全体を退避し、起動します。弾幕・配信者・設定・登録をすべて初期化します。元のフォルダーは復元用に保管してください。ボタンだけの問題なら再登録し、動画キャッシュだけなら再起動します。

## 調査を依頼する

操作を再現した後、「管理・ヘルプ」→「診断情報」を開きます。すでに開いている場合は「最新の状態に更新」を押してください。「表示中の診断情報をコピー」を押し、操作順、期待した結果、実際の結果、ブラウザー名、入力欄の種類を添えます。リアクションの問題なら、種類・回数・間隔と「リアクションの実行結果」も確認します。

ページ操作では操作名、処理段階、結果が表示されます。「クリア前の確認」と「クリアキー送信」で、クリア操作がどこまで進んだか分かります。アプリは入力欄の本文を読み取らないため、空になったかは画面で確認してください。結果の `enter_sent` はEnterキーを送ったことを示します。YouTubeに投稿されたかはチャット画面で確認できます。

診断コピーはアプリの版・OS・ブラウザー種別・処理状態・時間を含み、弾幕本文・動画URL・配信者名・保存先を含みません。リアクションの実行結果にはボタン名やエラー本文が入る場合があります。実行結果も共有するときは、表示内容を確認してください。
