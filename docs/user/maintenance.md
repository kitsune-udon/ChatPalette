# 保守・トラブル対処

[READMEへ戻る](../../README.md) · [利用ガイド](guide.md)

## 困ったとき

| 症状・表示 | 確認すること |
|---|---|
| 起動できない | AutoHotkey v2で開いているか、すべての `.ahk`・`.ps1` と `VERSION` が揃っているか確認します。フォルダーへの書き込み権限も必要です。 |
| パネルが見つからない | Ctrl＋Alt＋Q、またはタスクトレイの「ChatPaletteを開く」を使います。×で閉じても常駐は継続します。 |
| 弾幕キーが反応しない | ブラウザーを最前面にしてチャット欄またはコメント欄をクリックします。弾幕の編集画面でそのキーを割り当てているか、編集中のダイアログや別の処理が開いていないか確認します。 |
| チャンネル未連携／判別できない | 対象動画からパネルを開き、管理画面で配信者を選び、チャンネル連携を行います。手動運用なら自動判別をOFFにします。 |
| 「このブラウザーの登録が必要」 | 「操作・サポート」から操作ボタンを登録します。 |
| 「登録したメニューが見つかりません」 | ♡に重ねて5種類を表示し、「② 送らずに確認」を試します。改善しなければ再登録します。 |
| 「5種類を識別できませんでした」 | メニューを表示したまま登録し直します。「リアクションの実行結果」の不足・重複情報を確認します。 |
| 「動画が変わった」「操作先が変わった」 | 対象動画を最前面に戻し、メニューを開いてから改めて実行します。 |
| 「操作結果を確認できませんでした」 | 直前の操作が実行済みかどうかは不明です。結果と画面を確認してから次の操作を判断します。自動再送はしません。 |
| 25msでも期待ほど速くない | 25msは検出・操作を含む処理開始どうしの目標間隔です。処理に25ms以上かかる場合やOSのタイマー精度により、指定を超えます。待機なしも処理自体の時間を短縮する設定ではありません。表示の「平均開始間隔」は、操作に成功した処理の開始時刻どうしで測ります。YouTube側の受理間隔ではありません。 |
| 「登録情報を操作用プロセスへ反映できませんでした」 | 操作を停止し、次の操作でDBの登録情報を再同期します。登録直後の同期失敗でもDBに保存した情報は失われません。 |
| 「登録情報を保存できませんでした」 | 以前のボタン登録は維持されます。`data/` の書き込み権限を確認して再登録します。 |
| 「保存できませんでした」 | フォルダーが書き込み可能か、ファイルが読み取り専用になっていないか確認します。通常の編集では保存成功後に設定を確定します。 |

登録・確認時のスクリーンショット撮影は必須ではありません。別アプリへ切り替えるとリアクションメニューが閉じることがあります。

## 保存されるファイル

保存先は `main.ahk` と同じ階層にある `data/` です。フォルダーがなければ起動時に作成します。設定はSQLiteで保存します。旧ルート配置のファイルは自動移動しません。

| ファイル | 内容 | 存在しない場合 |
|---|---|---|
| `settings.db` | 配信者、弾幕、チャンネル連携、自動判別、リアクション設定・ボタン登録 | 旧 `data/settings.ini` があれば検証して移行。なければ初期値で作成し、配信者・弾幕は0件 |

設定ファイルがなくても起動できます。動画キャッシュのファイルは作成しません。

旧リアクション登録情報の移行に失敗した場合は、元ファイルを変更せず起動時の復旧画面で案内します。弾幕は引用符や前後の空白も保存しますが、旧版ですでに失われた文字は自動復元できません。

動画情報キャッシュは常駐プロセスのメモリだけに保持します。アプリや常駐プロセスの再起動後は再取得します。[保持期間・保存の仕組み](../developer/architecture.md#動画情報キャッシュ)は設計資料に記載しています。

## バックアップ・復元

起動中はタスクトレイの「弾幕・設定をバックアップ」から、新しいファイル名を指定します。弾幕・配信者・共通設定・リアクションボタン登録をまとめて保存します。

手動でコピーする場合は、タスクトレイの「Exit」で正常終了してから `data/settings.db` をコピーします。起動中のDB本体だけをコピーしないでください。異常終了後の `settings.db-journal` 等は復旧に必要な場合があるため削除せず、まず通常起動・正常終了してください。

復元はアプリを終了し、現在のDBと付随ファイルを一緒に別の場所へ退避してから、バックアップを `data/settings.db` として配置します。古いジャーナルを復元先へ混ぜないでください。ボタン登録もDBから復元されます。

動画キャッシュはファイルへ保存せず、バックアップも不要です。別PCや別ブラウザー環境では、復元したボタン登録を「② 送らずに確認」で確認してください。

## 初期化

アプリを終了してから、`data/` 内の初期化したいファイルを削除または退避します。

- 配信者・弾幕・共通設定・ボタン登録を初期化：`settings.db`。移行前の `settings.ini`・`reaction_selectors.json` が残っていれば、それも退避します。残すと再移行します。
- ボタン登録を修正する場合：「操作・サポート」から対象ブラウザーで再登録します。旧JSONを削除してもDB内の登録は消えません。
- 動画情報のキャッシュを初期化：アプリを再起動します。

DB・INI・JSONを退避すると新規状態になります。起動中に設定を削除しないでください。読み込みに失敗すると「再試行」「無視」「中止」を選ぶ復旧画面が表示されます。「無視」と次の確認に同意すると、元のDB・付随ファイル・移行元INI・旧登録JSONを日時付きの名前へ退避して初期化します。退避に失敗した場合は初期化しません。空・破損・未対応形式のDBを自動的に初期化することはありません。

## 更新

0.4.2では動画キャッシュのファイル保存を廃止しました。旧 `data/video_metadata_cache.json` は使用しないため削除できます。リアクション登録の更新では常駐プロセスと動画キャッシュを維持します。

0.4.1では、DBを形式2へ更新する際に `data/reaction_selectors.json` を検証して取り込みます。元JSONは移行前の控えとして残し、以後は読み書きしません。新規DBの作成時も同様です。移行成功後は旧JSONを削除できます。形式2のDBは0.4.0で開けません。

0.4.0から設定をSQLiteへ変更しました。`data/settings.ini` は初回起動時に検証・移行し、そのまま移行前の控えとして残します。以後の編集は `settings.db` に保存します。重複したチャンネル連携などを移行できない場合は、元INIを変更せず起動を中止できます。

旧版へ戻す場合、旧版はDBを読み込めません。残したINIは移行前の状態なので、移行後の編集は反映されません。旧版と新版を同じデータフォルダーで交互に使わないでください。移行後のデータを保持した復帰には別途変換が必要です。

アプリを終了し、配布されたコード一式を同時に更新します。既存の `data/` は残します。`VERSION` もコードと一緒に更新します。新旧のモジュールを混在させないでください。更新前に設定のバックアップを取ると、必要な場合に戻せます。

## 常駐処理と障害時の動作

ブラウザーを調べる必要が生じた時点で、補助のPowerShellプロセスを起動します。アプリとは名前付きパイプで通信します。

補助プロセスが終了した場合や通信に失敗した場合、その操作は失敗または結果不明として扱います。次に必要になったときに補助プロセスを起動し直します。失敗したリアクションを自動的に再送することはありません。

調査を依頼するときは、実行した操作、ブラウザー名、表示されたメッセージ、「診断情報」と必要に応じて「リアクションの実行結果」を添えてください。「リアクションの実行結果」には検出したボタン名やエラーメッセージが含まれます。診断情報のコピーとは内容が異なるため、共有前に確認してください。設定ファイル全体には個人の弾幕やチャンネル連携情報が含まれます。

「診断情報」は開いた時点の状態を表示します。状態が変わったら「最新の状態に更新」を押してください。「表示中の診断情報をコピー」で、その取得日時の情報と調査用コードをコピーします。コピー完了は画面下部に表示されます。弾幕本文・動画URL・配信者名・保存先のパスはコピーに含みません。×またはEscで診断画面だけを隠します。

設定の件数と実際の項目が一致しない場合も、起動時の復旧画面で扱います。上限は配信者10000件、弾幕合計100000件、名前・本文等の文字列合計がUTF-16換算32MiBです。DB本体は索引等を含め128MiBまでです。元のファイルを確認し、必要ならバックアップから復元してください。
