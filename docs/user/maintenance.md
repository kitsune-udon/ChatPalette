# 保守・トラブル対処

[READMEへ戻る](../../README.md) · [利用ガイド](guide.md)

## 困ったとき

| 症状・表示 | 確認すること |
|---|---|
| 起動できない | AutoHotkey v2で開いているか、すべての `.ahk`・`.ps1` と `VERSION` が揃っているか確認します。フォルダーへの書き込み権限も必要です。 |
| パネルが見つからない | Ctrl＋Alt＋Q、またはタスクトレイの「ChatPaletteを開く」を使います。×で閉じても常駐は継続します。 |
| 弾幕キーが反応しない | ブラウザーを最前面にしてチャット欄またはコメント欄をクリックします。弾幕の編集画面でそのキーを割り当てているか、編集中のダイアログや別の処理が開いていないか確認します。 |
| チャンネル未連携／判別できない | 対象動画からパネルを開き、管理画面で配信者を選び、チャンネル連携を行います。手動運用なら自動判別をOFFにします。 |
| 「このブラウザーの登録が必要」 | 「操作・サポート」から操作ボタンを登録します。 |
| 「登録したメニューが見つかりません」 | ♡に重ねて5種類を表示し、「② 送らずに確認」を試します。改善しなければ再登録します。 |
| 「5種類を識別できませんでした」 | メニューを表示したまま登録し直します。「リアクションの実行結果」の不足・重複情報を確認します。 |
| 「動画が変わった」「操作先が変わった」 | 対象動画を最前面に戻し、メニューを開いてから改めて実行します。 |
| 「操作結果を確認できませんでした」 | 直前の操作が実行済みかどうかは不明です。結果と画面を確認してから次の操作を判断します。自動再送はしません。 |
| 25msでも期待ほど速くない | 25msは検出・操作を含む処理開始どうしの目標間隔です。処理に25ms以上かかる場合やOSのタイマー精度により、指定を超えます。待機なしも処理自体の時間を短縮する設定ではありません。表示の平均操作間隔もYouTube側の受理間隔ではありません。 |
| 「登録情報を保存できませんでした」 | 以前のボタン登録は維持されます。`data/` の書き込み権限を確認して再登録します。 |
| 「保存できませんでした」 | フォルダーが書き込み可能か、ファイルが読み取り専用になっていないか確認します。通常の編集では保存成功後に設定を確定します。 |

登録・確認時のスクリーンショット撮影は必須ではありません。別アプリへ切り替えるとリアクションメニューが閉じることがあります。

## 保存されるファイル

保存先は `main.ahk` と同じ階層にある `data/` です。フォルダーがなければ起動時に作成します。ルートにあった3ファイルは起動時に移動します。移行先に同名ファイルがある場合はそちらを優先し、旧ファイルを上書き移動しません。

| ファイル | 内容 | 存在しない場合 |
|---|---|---|
| `settings.ini` | 配信者、弾幕、チャンネル連携、自動判別、リアクション設定 | 起動時に初期値で作成。配信者・弾幕は0件 |
| `reaction_selectors.json` | ブラウザーごとのリアクションボタン登録 | 未登録として動作。登録成功時に作成 |
| `video_metadata_cache.json` | 動画ID、配信者、チャンネル、取得日時のキャッシュ | 必要に応じて再取得・保存 |

3ファイルともなくても起動できます。JSONファイルが起動直後に作られないのは正常です。

リアクション登録の形式が壊れている場合、その登録は使用しません。「操作・サポート」から再登録してください。弾幕は引用符や前後の空白も保存しますが、旧版ですでに失われた文字は自動復元できません。

動画情報キャッシュは削除しても必要に応じて再取得されます。[保持期間・保存の仕組み](../developer/architecture.md#動画情報キャッシュ)は設計資料に記載しています。

## バックアップ・復元

1. タスクトレイの「Exit」で終了します。
2. `data/settings.ini` と、必要なら `data/reaction_selectors.json` を別の場所へコピーします。
3. 復元する場合もアプリを終了し、`data/` 内に同じ名前で戻してから起動します。

動画キャッシュは再取得できるため、通常はバックアップ不要です。別PCや別ブラウザー環境では、復元したボタン登録を「② 送らずに確認」で確認してください。

## 初期化

アプリを終了してから、`data/` 内の初期化したいファイルを削除または退避します。

- 配信者・弾幕・共通設定を初期化：`settings.ini`
- リアクションボタン登録だけを初期化：`reaction_selectors.json`
- 動画情報のキャッシュだけを初期化：`video_metadata_cache.json`

すべて削除すると完全な新規状態になります。起動中に削除すると、メモリ上の設定やキャッシュが再保存される場合があります。設定の読み込みに失敗した場合は「再試行」「無視」「中止」を選ぶ復旧画面が表示されます。「無視」を選び、次の確認で同意すると、元のINIを `data/settings.ini.backup-日時-番号` に退避して初期化します。退避に失敗した場合は初期化しません。修正して再試行する場合、画面に表示された設定項目を確認してください。

## 更新

0.3.0ではリアクションの配信者別設定を廃止しました。旧設定は適用せず、保存済みの共通の種類・回数・間隔・キーを使います。弾幕は保持し、従来の先頭2件を明示的なキー割当に移行します。設定形式更新前に `data/settings.ini.backup-日時-番号` を作成します。初回は管理画面で割当と共通の標準設定を確認してください。

アプリを終了し、配布されたコード一式を同時に更新します。既存の `data/` は残します。`VERSION` もコードと一緒に更新します。新旧のモジュールを混在させないでください。更新前に設定のバックアップを取ると、必要な場合に戻せます。

## 常駐処理と障害時の動作

ブラウザーを調べる必要が生じた時点で、補助のPowerShellプロセスを起動します。アプリとは名前付きパイプで通信します。

補助プロセスが終了した場合や通信に失敗した場合、その操作は失敗または結果不明として扱います。次に必要になったときに補助プロセスを起動し直します。失敗したリアクションを自動的に再送することはありません。

調査を依頼するときは、実行した操作、ブラウザー名、表示されたメッセージ、「診断情報」と必要に応じて「リアクションの実行結果」を添えてください。「リアクションの実行結果」には検出したボタン名やエラーメッセージが含まれます。診断情報のコピーとは内容が異なるため、共有前に確認してください。設定ファイル全体には個人の弾幕やチャンネル連携情報が含まれます。

「診断情報」は開いた時点の状態を表示します。状態が変わったら「最新の状態に更新」を押してください。「表示中の診断情報をコピー」で、その取得日時の情報と調査用コードをコピーします。コピー完了は画面下部に表示されます。弾幕本文・動画URL・配信者名・保存先のパスはコピーに含みません。×またはEscで診断画面だけを隠します。

設定の件数と実際の項目が一致しない場合も、起動時の復旧画面で扱います。上限は設定ファイル32MiB、配信者10000件、弾幕合計100000件です。元のファイルを確認し、必要ならバックアップから復元してください。
